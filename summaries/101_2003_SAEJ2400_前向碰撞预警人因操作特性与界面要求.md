## 一、研究背景与问题

### 1.1 领域现状
摘要可确证：**FCW 系统被定义为车载系统（onboard systems）**，其功能是**发出提示（alerts）以协助驾驶员避免撞上另一辆运动中或静止的机动车的尾部（striking the rear end of another moving or stationary motorized vehicle）**。这一定义中的两个要点对本课题至关重要：① **场景限定为追尾（rear-end）**；② **目标物限定为「机动车（motorized vehicle）」**，涵盖运动与静止两种状态。**行人、骑行者、动物、固定障碍物均不在该定义之内。** 领域综述、事故统计与标准制定背景：**摘要未报告**。

### 1.2 研究缺口

## 四、主要结果与发现（摘要原文层面）

1. **FCW 的功能定义**：车载系统，发出提示以协助驾驶员**避免撞上另一辆运动中或静止的机动车的尾部**。
2. **文件交付内容**：FCW 操作者界面的构成要素 + 系统要求 + 测试方法。
3. **适用范围（apply to）**：**乘用车（passenger vehicles）**的 **原装（original equipment）与后装（aftermarket）** FCW 系统；乘用车明确包括 **轿车（cars）、轻型卡车（light trucks）、厢式车（vans）**。
4. **排除范围一（does not apply to）**：**重型卡车（heavy trucks）**。
5. **排除范围二（does not address）**：**与自适应巡航控制（ACC）集成相关的集成议题（integration issues）**；且文件明确警示——**本文件的部分内容对于「与 FCW 集成的 ACC 系统」可能是不恰当的（could be inappropriate）**。

> 摘要未报告：任何界面要素的具体形式、预警时机、分级策略、模态要求、测试通过判据。

## 五、对 AR-HUD 行人预警时空设计的启示

### 5.1 时间参数（本课题核心）

#### 5.1.0 对「自适应/动态预警阈值」的贡献（本课题四篇动态阈值证据之一）

**本篇在四篇动态阈值文献（idx 73 / 91 / 95 / 101）中的角色：它是被另外三篇「超越」的那个基准——即「固定阈值 / 静态标准范式」的制度化代表。四篇之所以能构成一条论证链，正是因为有本篇作为起点与对照。**

> **前置说明**：本篇是**标准文件（SAE Information Report）**，不是实证研究，本身**不主张**动态阈值。它对本论点的贡献是**反向的、结构性的**——它定义了「固定/统一规格」这一范式的内容与边界，从而使「该范式为何不足」成为一个可论证的命题。

| 维度 | 本篇（SAE J2400, 2003）在论证链中的作用 |
|---|---|
| **论点第一句：固定 TTC 阈值不足** | 本篇是**「统一规格」范式的制度化文本**：它为乘用车 FCW 规定统一的操作者界面要素（elements）、要求（requirements）与**测试方法（test methods）**。**「可测试」这一属性必然要求「规格可复现、不随驾驶员变化」——这正是固定阈值范式的制度根源。** 因此，当 idx 95（2005）、idx 91（2023）、idx 73（2026）主张按驾驶员标定时，它们实际上是在挑战本篇所代表的这一范式。**注意：本篇摘要未给出任何阈值数值或时机要求，故「本篇采用固定阈值」这一判断是基于其「标准 + 测试方法」的文件性质所作的推断，须以全文核验其是否含 crash alert timing 条目。** |
| **论点第二句：须按驾驶员状态标定** | **本篇的反向证据价值**：标准面向的是「典型驾驶员（typical driver）」这一虚构主体，**不含任何按驾驶员状态（分心/激进/疲劳）分化的条款**（摘要未见此类内容）。→ 本篇因此成为「**驾驶员异质性在既有规范中缺位**」这一缺口的**直接文本证据**。**这是本课题第一章缺口论证可引用的最有力材料：不是学界没研究，而是规范层面至今没有条款。** |
| **论点第三句：须按运动学标定** | 本篇明确**排除重型卡车（does not apply to heavy trucks）**——这一排除本身即承认**车辆运动学能力差异大到无法用同一套规格覆盖**。**这是本篇内部最锋利的一处自我限定：标准以「分车型另立文件」的方式处理运动学差异，而 idx 73（重型卡车 A-TTC）与 idx 85/86（公交）正是在这一被排除的领域中工作，且都得出「阈值须显著更早/更动态」的结论。** 换言之：**J2400 用「排除」承认了运动学依赖性，动态阈值文献则用「函数化」处理了它。** |
| **与 idx 95 的时间关系（本篇最重要的一处对照）** | **J2400 发布于 2003 年 8 月；idx 95（Miyoshi et al., SAE 2005-08-0554）发表于 2005 年，即标准发布仅两年后，同一 SAE 体系内就出现了「适配驾驶员特性」的技术论文。** → **静态标准在发布时就已被从业者认为不足以覆盖驾驶员差异。**（**仅为两份文献的年份并置，idx 95 是否引用或批评 J2400 未经核实。**） |
| **规范层面的真实张力（本课题必须处理的设计决策）** | **个性化阈值与标准化测试在原则上抵触**：J2400 要求可复现的测试方法；而 idx 73 的多模态动态阈值、idx 91 的 DQN 隐式策略**既无显式阈值、又不可解释**，难以通过标准化测试。**由此冲突直接导出本课题规范文档应采用的结构：「区间 + 个性化浮动」双层规范**——标准层规定阈值的**可接受区间与最坏情形下界**（如「无论如何不得晚于 X」，对应 J2400 的可测试性要求），实现层允许在区间内按驾驶员状态浮动（对应 73/91/95 的自适应要求）。**这是本节对本课题最有实质价值的产出。** |

**四篇合读的完整论证链（与 `73_2026_Wang_...md`、`91_2023_Sun_...md`、`95_2005_Miyoshi_...md` 中同一小节保持一致，此处从本篇视角复述）**：
1. **本篇 idx 101（SAE J2400, 2003 年 8 月）**：确立 FCW 人因界面的**静态标准框架**——面向「典型驾驶员」的统一规格，价值在统一性与可测试性，代价在无法容纳驾驶员异质性（并以「排除重型卡车」的方式回避运动学差异）；
2. **idx 95（Miyoshi et al., 2005, SAE 2005-08-0554）**：标准发布两年后即提出「**适配驾驶员特性**」——**「阈值应因人而异」的历史起点**（标题级证据，摘要未获取）；
3. **idx 91（Sun et al., 2023, CICTP）**：用**实时 DRT 估计 + 深度 Q 网络**实现可学习的触发策略，准确率 **94%**、真正率 **49%**，明确优于 TTC 经典模型与既有自适应模型——**方法学突破**；
4. **idx 73（A-TTC, 2026, SSRN 预印本）**：用 **569 辆卡车、3,519 条视频核验的 FCW 触发事件**证明动态标定可把**事件级骚扰报警占比压到 13.74%**、总体准确率 81.42%、威胁事件召回 89.25%（正式版口径；**未报告固定阈值对照基线**，预印本的 25.16% → 12.21% 已作废），且避险成功率不降——**规模化验证与收益量化**。
> **结论句（可直接写入论文）：从静态标准（2003，本篇）、个性化设想（2005）、可学习策略（2023）到大样本收益量化（2026），四条证据共同表明——单一固定 TTC 阈值既无法覆盖驾驶员反应时的个体与状态差异，也无法覆盖运动学场景的多样性（J2400 本身即以「排除重型卡车」承认了后者）；预警阈值必须按「驾驶员状态 × 车辆运动学能力」动态标定。而规范层面的应对方式，应是「统一区间 + 个性化浮动」的双层结构，而非在「统一规格」与「完全个性化」之间二选一。**

#### 5.1.2 基于摘要的推断（待全文核验）
1. J2400 把「FCW 界面」作为可独立标准化的对象（elements + requirements + test methods 三段结构），说明**界面要求可与触发算法分离标准化**。→ 推断：本课题的 AR-HUD 行人预警亦可采用「触发逻辑（时间参数）」与「呈现规范（空间参数）」分离的双层规范结构。**此为推断。**

- **本篇的特殊地位（必须在论文中显式说明）**：本篇是**本库唯一的正式标准/信息报告类文献**。其证据地位与实验研究根本不同——它不提供可比较的实证数值（无样本量、无统计量、无阈值），而提供**行业共识的规范性边界与术语定义**。因此：① **不可与实验研究并列做「一致/冲突」的数值比对**；② 应用于「工程可行性与合规性」论证，而非「效应量」论证；③ 引用时应写为规范引用格式（SAE J2400, Aug 2003），而非期刊文献格式。

- **可用于章节**：「FCW 的工程定义与行业规范」小节（术语与功能定义的权威来源）；「本课题的适用边界与局限」小节（**最重要的用途**，见下）；「界面要求的规范化结构」方法学讨论（elements + requirements + test methods 三段结构）。

- **与本课题最关键的关联——一条必须显式写入论文的局限**：
  > **本课题的行人预警不在 J2400 的覆盖范围内。** J2400 明确把 FCW 定义为「协助驾驶员避免撞上另一辆运动中或静止的**机动车尾部**」的系统，即**只针对追尾（rear-end）场景**。因此**不能直接把 J2400 的界面要求迁移到行人横穿场景**。理由有三：① **目标物运动方向不同**——追尾场景中目标沿本车纵轴运动，行人横穿场景中目标横向切入，二者的视觉搜索区域、偏心度与图形锚定策略均不同；② **可用回避手段不同**——追尾以纵向制动为主，行人横穿常需制动 + 转向的组合，界面需承载方向信息；③ **目标可探测性不同**——机动车尾部有刹车灯等强线索（对照 idx 74：前车带刹车灯以 0.8 g 减速，驾驶员**无预警**时也能在 **0.72 s** 内松油门、**1.14–1.20 s** 内制动、**零碰撞**），而行人横穿常无前置线索（对照 idx 71：无预警基线下驾驶员到**距冲突点 1.5 s** 才猛制动、**碰撞率 44.1%**）。→ **同一套界面要求在两类场景中的边际价值差异极大，这是本课题必须显式声明的局限。**

- **与已收录文献的一致之处**：
  1. **与 idx 74（Abe & Richardson 2006）的场景一致**：74 研究的正是 J2400 覆盖的**前车减速追尾**场景（前车带刹车灯以 **0.8 g** 减速），因此 74 的界面/时机结论（听觉报警 **2.0 s / 4000 Hz**、报警须早于驾驶员自身松油门时点 **0.72 s**）**落在 J2400 的有效域之内**，可与 J2400 相互支撑。
  2. **与 idx 77（Lind 2007）的场景一致且互补**：77 比较 CWHUD 与方向盘/仪表/HHDD 四种呈现位置，得 CWHUD 快约 **200 ms**（**F(3,45)=10.8, p<0.0001**），并给出单次预警 **1.2 s**、闪烁 **4 Hz**（亮 0.15 s / 灭 0.1 s，占空比 **60%**）。这正是 J2400 所描述的「operator interface elements」类型的实证填充，且同为**追尾场景 + 车载界面**，与 J2400 的适用范围完全吻合。→ **建议在论文中把 J2400 作为规范框架、77 作为该框架内的实证数值来源并引。**
  3. **与 idx 76（Thammakaroon 2012）的对象一致**：76 评测的是实车 FCW（报警比真实制动**晚 1.47 s**，跟车判据 2.0 → 1.6 s），属 J2400 覆盖的原装/后装乘用车 FCW 范畴。

- **与已收录文献的冲突之处（必须显式指出）**：
  1. **与 idx 85 / idx 86（Chang & Chang，交叉口公交-行人预警）的适用范围互斥——这是本篇最重要的一处冲突**：J2400 **明确不适用于重型卡车（heavy trucks）**，而 85/86 的对象是**公交**；且 J2400 **只覆盖追尾/机动车目标**，而 85/86 的对象是**行人横穿**。→ **两条边界同时被违反**，因此**J2400 的任何条目都不能用于论证公交-行人预警的合规性**，反之 85/86 的公交参数（idx 86 全文给出的 Twd = 6.07 s（视觉）/ 6.28 s（语音）、行人步速、检测器距离等）也**不能用于论证 J2400 场景**。论文中若同时引用这两组文献，必须显式声明车型与场景的双重不可迁移性。
  2. **与 idx 78（Large 2019）的范畴冲突**：78 的 Daimler 级联（**4.0 → 2.6 → 1.6 → 1.1 s**，级间 1.4/1.0/0.5 s）与 PROSPECT 迫近预警（**TTC 1.8 s**）是**行人**场景的分级时序；J2400 覆盖追尾场景且**摘要未报告任何分级要求**。→ 不得把 78 的行人级联当作「符合 J2400 的分级方案」。
  3. **与 idx 84（Char 2022）的范畴冲突**：84 处理的是**行人与骑行者** FCW 的触发时机（3700+ 事故重建 + 200 人模拟器反应时分布），其目标物类别明确超出 J2400 的「motorized vehicle」定义。
  4. **潜在的时代性冲突（无法判定）**：J2400（2003）成文时不存在 AR-HUD 与世界锁定图形，其 interface elements 是否与 AR 呈现方式相容——**摘要未报告具体条目，无法判定**；论文中只能写「其条目是否覆盖 AR 世界锁定图形无法核实（未获取全文）」。

- **引用注意**：① 表头必须保留「**仅摘要（来源：Crossref）**」；② **引用摘要文字前必须反转义**（原始 Crossref 字段含 `&lt;div&gt;` 等 HTML 转义），不得把标签写入论文；③ 引用格式应为标准引用（SAE J2400, *Human Factors in Forward Collision Warning Systems: Operating Characteristics and User Interface Requirements*, SAE Information Report, Aug 2003）；④ **不得赋予其实验证据的地位**，也不得从中引出任何数值；⑤ 引用时必须同时给出适用/排除范围（乘用车、含原装与后装、不含重型卡车、不涉 ACC 集成）；⑥ **凡涉行人场景，必须写明其不在 J2400 覆盖范围内**。

### 7.x 证据等级、引用禁则与补全途径（本批次统一登记项）

- **证据等级：B**。可作为**工程锚点的边界条件依据**（文件性质、覆盖对象、排除范围），**不得用作数值锚点**——摘要（Scope 段）不含任何界面要求数值、时机阈值或测试方法参数。**凡以 J2400 为工程锚点时，必须同时声明四条边界：① 仅覆盖追尾场景、目标物为机动车（行人完全不在覆盖范围内）；② 仅适用乘用车（轿车/轻型卡车/厢式车），明确不适用重型卡车；③ 覆盖原装与后装；④ 不涉及 ACC 集成，且文件自陈部分内容对 ACC+FCW 集成系统可能不恰当。** 特别地：**若要论证「行人预警的界面要求已有标准依据」，不可引用 J2400。**
- **本篇对本课题设计规范的对标价值（补全理由，与 idx 64 并列为本批次最高）**：
  1. **条款语法的范式**：J2400 采用「elements（界面要素）+ requirements（要求）+ test methods（测试方法）」三段结构与 shall/should/may 语法。**本课题的规范交付物宜采用这一条款语法，承载 idx 64（Yamin 2024）的 AR 特有维度与本课题自身的时间参数** —— 即「J2400 的体例 + Yamin 的 AR 维度 + 本课题的时间参数」三者合成。
  2. **「触发算法」与「呈现规范」可分离标准化**：J2400 把 FCW 界面作为可独立标准化的对象，佐证本课题可采用「触发逻辑（时间参数）/ 呈现规范（空间参数）」双层规范结构。
  3. **「区间 + 个性化浮动」双层结构的由来**：J2400 的可测试性要求与 idx 73/91 的自适应阈值在原则上抵触（隐式策略无法标准化测试）。**由此冲突导出本课题规范应在标准层规定阈值的可接受区间与最坏情形下界（「无论如何不得晚于 X」），在实现层允许按驾驶员状态在区间内浮动**——这是本篇对本课题最有实质价值的产出。
  4. **缺口的文本证据**：标准面向虚构的「典型驾驶员」，无任何按驾驶员状态分化的条款，且以「排除重型卡车」的方式回避运动学差异。**这是「驾驶员异质性与运动学差异在既有规范中缺位」这一缺口的直接文本证据。**

  4. **补全后必须提取**：① 是否含 **crash alert timing** 条目及其数值；② 界面要素清单（模态、位置、颜色、亮度、图形、时长）；③ 测试方法与判定准则；④ 「典型驾驶员」的参数假设（反应时取值）；⑤ 分级/多级报警是否被规定。

> **Takeaway**：SAE J2400（2003-08）是本库唯一的标准类文献，它把 FCW 定义为「协助驾驶员避免撞上另一辆运动或静止**机动车尾部**」的车载系统，给出界面要素 + 要求 + 测试方法三段结构，**适用于乘用车（轿车/轻型卡车/厢式车）的原装与后装 FCW，明确不适用于重型卡车，且不涉及 ACC 集成议题（并自陈部分内容对 ACC+FCW 集成系统可能不恰当）**；**摘要不含任何时机阈值或界面数值**。对本课题最关键的推论是一条必须显式声明的局限：**行人横穿预警不在 J2400 覆盖范围内（其只针对追尾场景），因此不能直接把其界面要求迁移到行人场景**。
