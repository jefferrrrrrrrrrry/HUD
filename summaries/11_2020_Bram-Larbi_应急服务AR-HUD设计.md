## 一、研究背景与问题

### 1.1 领域现状
- 应急服务车（Emergency Services, ES）——救护、警务、消防——的首要目标是"快速、安全、有效"到达事件现场。但近年来由于城市人口与突发事件增多，"到达时间"被显著拉长——文献 [3] 提到"原本预计 8 min 的旅程被延长到 3 h 才能到达"。
- ES 车辆传统上以**警报器 + 警灯**来引起其他驾驶员让行，但研究指出：
  - 现有警报器（500–1500 Hz 扫频，Moore 等 2011）由于高背景噪声和人耳定位的非个体化 HRTF 误差，**普通驾驶员往往无法准确判断来车方位**；
  - 一项调查显示 **86% 的 ES 车在出警时使用警报器，但只有约 2/3 的旁车在 50 m 距离前能察觉，约 25% 的驾驶员完全听不见**（Saunders & Gough 2003）；
  - 加之现代车辆隔音良好、音乐播放、电话/导航/社交媒体等次要任务，使民用车辆驾驶员对 ES 车更加迟钝。
- ES 车上的 HDD（Head-Down Display，仪表板下方显示）也加重了**ES 司机本身**的认知负荷——他们必须兼顾导航、调度、伤患情况和高速变道。
- AR-HUD 被视为整合 V2V / AI 路径规划 + 全风挡 AR 投影、以"低认知负荷"提供决策辅助的关键技术（援引 Gabbard 2014、Charissis 系列工作）。

### 1.2 研究缺口
此前 ES 车 HUD 的研究主要针对单一驾驶任务，缺乏**综合考虑警报误判 + 司机分心 + 民用车驾驶员分心 + 不确定交通流**的设计框架。本文要为"应急 ES 车专用 AR-HUD"提出**系统性的设计要求**，包括"EV-to-CV"（Emergency Vehicle to Civilian Vehicle）通信中断民用车信息娱乐播放、AI 路径建议、全风挡投影界面等。

### 1.3 核心研究问题
- RQ1：在缓行 / 拥堵交通条件下，民用车驾驶员从事哪些次要活动以致无法及时让行？
- RQ2：基于上述行为，应当为 ES 车设计什么样的 AR-HUD 系统？应当具备哪些 HMI 设计要求？

## 二、研究方法

### 2.1 被试与样本
- N = 50 名驾驶员，全部持英国有效驾照；
- 男 40 / 女 10；
- 年龄区间 18–60 岁；
- 论文未明确报告平均年龄、平均年驾驶里程的统计值（仅在问卷第一部分采集，未在结果中分组报告）；
- 招募时还另外组织了 5 人的 ES 司机焦点小组（preliminary focus group），用于挖掘需求。

### 2.2 实验设计
- 类型：以**问卷调查 + 焦点小组 + 接地理论（grounded theory）**为主的**质性 + 描述统计**研究；
- 自变量：无；
- 因变量：18 项关于驾驶时次要活动频率的自报量表（"非常频繁 / 经常 / 有时 / 偶尔 / 从不"）。

### 2.3 实验材料与设备
- 问卷 25 题，分两部分：
  - 第一部分：人口学 + 年里程 + 道路类型 + 与 ES 车的相遇频率；
  - 第二部分：20 题（最终展示 18 题），询问缓行/堵车时的驾驶行为；
- 焦点小组：5 名 ES 司机，质性访谈；
- 论文还展示了一个 VR 驾驶模拟器中的 ES 车 AR-HUD 原型（Figure 5），具体使用 Charissis 团队既有的"全风挡 AR 投影 + 手势识别"方案[5, 6, 7, 14, 15]。
- AR-HUD 原型刺激规格（颜色 RGB/形状/动效/空间面/FOV/场景几何）：**论文未明确报告**详细参数。

### 2.4 任务与流程
1. 招募 50 名民用车驾驶员；
2. 填写 25 题问卷（含 18 题次要活动量表）；
3. 数据处理为百分比频次；
4. 与 5 名 ES 司机焦点小组的需求做对照；
5. 综合得出 AR-HUD 设计框架（Section VI）。

## 三、关键指标与测量
- 自报频次（百分比） 18 项次要任务：
  - 发短信、读短信、上网、读笔记、对清单、日历、音乐、电话（拨/接、语音/视频）、社交网络、新闻等。
- 焦点小组定性观点：哪些技术（如交通监控、Mayday、自动碰撞通知）有用，哪些（如可变信息标志 VMS）受限于路网基础设施而难以推广。

## 四、主要结果与发现

### 4.1 问卷主要数字（Figure 3 / 4）
- **发送短信**："非常频繁 + 经常 + 有时"合计 34%；
- **阅读手机短信** = 60%；
- **使用导航系统** = 76%；
- **驾驶中上网** = 40%；
- **阅读 / 写笔记** = 16%；**对清单（checklists）** = 8%；
- **音乐播放/选歌** = **90%**（最高，与"听不到警报器"高度相关）；
- **拨打音频电话** = 75%；**接听音频电话** = 80%；
- **视频通话**：拨打 6% / 接听 5%（低）；
- **新闻更新** = 20%；
- **使用社交网络** = 40%（与车机内置社交媒体功能呼应）。

### 4.2 焦点小组结论
- ES 司机最大的痛点不是路况本身，而是**民用车驾驶员对快速变化的交通状况注意力下降**，因此让行延迟；
- 现有"交通监控 + Mayday + 自动碰撞通知"已部分缓解；
- 可变信息标志（VMS）受路网基建限制不普适；
- 一致呼吁"实时变道建议（AI）+ 全风挡 AR 投影（HUD）"的组合解决方案。

### 4.3 提出的 AR-HUD 设计框架（Section VI）
1. **EV-to-CV 通信**：当 ES 车接近时，**自动暂停**附近民用车的车机信息娱乐系统（音乐、电话、社交），强制把警示推送到民用车的 HUD；
2. **AI 路径规划**：基于多场景训练，向 ES 司机给出动态变道与避撞建议；
3. **全风挡 AR-HUD**：实时叠加路径、其他车辆动作预测、推荐位置等。

## 五、对 AR-HUD 时空设计的启示

### 时间元素（出现时机 TTC、持续时长、分级间隔）
- 论文未给出具体 TTC、持续时长数值；
- 但暗含的时序原则：
  - **接近 ES 车出现 → 民用车 HUD 立即激活预警 + 中断娱乐**；
  - 在 ES 司机端，导航辅助应保持"中速持续流"，避免脉冲式高速突变（援引 [22, 5]）；
  - 持续监控 V2V 信号，给出"在前方多少秒/米后变道"的连续提示。

### 空间元素（平面 2D）
- 论文未具体规定颜色 RGB / 形状参数；
- 借鉴自 Charissis 团队既有工作（[5,6,7,14]），AR-HUD 用箭头 + 路径线 + 推荐位置的组合。

### 空间元素（立体：分布面 / FOV / 相对位置）
- **全风挡 AR-HUD（Full-Windshield HUD）**：整个挡风玻璃可作为投影区，是 ES 用例独有需求（同时显示路径、邻车意图、行人/障碍物位置）；
- 信息空间需要与"道路 + 邻车 + ES 车"三个空间锚定，对深度感与立体感要求更高；
- 论文未直接给出 FOV 角度，但作者团队既往工作中常用 ~60° 水平、30° 垂直窗口（与 idx 10 一致）。

### 设计原则与适用边界
- 原则 1：**双向预警**——AR-HUD 不仅服务驾驶员，还应通过 V2V 通知附近车辆；
- 原则 2：**中断娱乐**——遇紧急时，民用车的非必要信息源（音乐/通讯）应自动暂停；
- 原则 3：**AI + AR 协同**——AI 给出操控建议，AR 把建议直接锚定到外部场景；
- 原则 4：在拥堵 / 缓行场景下，预警最关键，因为驾驶员此时最易分心；
- 适用边界：当前 V2V/V2X 通信标准与 AR 硬件尚未普及，原型仅在 VR 模拟器中测试；问卷样本 50 人偏小，男女比 4:1 也不均衡。

## 六、本文局限性与未来工作
1. **样本不平衡**：男女 4:1，年龄跨度大但未做细分；
2. **方法学**：以问卷 + 接地理论的质性研究为主，无对比实验，缺少行为数据；
3. **AR-HUD 设计参数缺失**：本文偏概念框架，未给出颜色/形状/TTC 等可量化规范；
4. **未来工作**：
   - 完成最终原型并在 VR 模拟器中开展定量评估；
   - 与 ES 司机做真实车评估；
   - 与 V2V/V2X 通信标准对接，建立 EV-to-CV 暂停指令协议。

## 七、与本研究主题（HUD/AR-HUD 行人标注的时间空间设计规范）的关联

本文与本研究综述的主线"行人 AR-HUD 标注"虽**不在同一应用场景**，但提供了以下侧面的支撑：

1. **驾驶员分心的频度数据**：高达 60% 的人在驾驶中读短信、90% 在播音乐、76% 在用导航、80% 在接电话——这些是 AR-HUD 行人预警必须考虑的"基线分心环境"。任何预警设计都必须假设驾驶员处于次要任务负荷下，才能保证生态有效性。
2. **多方协同预警思路**：本研究对"V2V/V2X + AR-HUD"组合的强调，可启发车端行人预警进一步整合"V2P（Vehicle-to-Pedestrian）"——即同时向行人发出告警（与 idx 10 形成耦合）。
3. **全风挡 AR-HUD 的边界规范**：当行人 + 其他车辆 + 路径需同时叠加时，FOV 不能再局限于传统 6° × 3° 的 HUD 投影窗，而是要扩展到全风挡级，这是行人标注空间规范的重要工程考虑。
4. **警报形式互补**：本文揭示了听觉警报的天然定位缺陷——同样的逻辑可用于支持"视觉 AR 标注**优于**单纯听觉提示行人危险"的论证。
5. **场景应用启示**：ES 车场景下行人冲入风险更高（紧急车辆穿行、行人对警报反应迟缓），可作为 AR-HUD 行人标注的"高优先级用例"加入设计规范。
6. **时间维度补充**：在 ES 用例下，AR-HUD 应当**先于警报器**给民用车驾驶员视觉提示，将"听觉→视觉"的反应链前移；这条原则可推广到行人预警——"AR 标注先于行人冲出动作就出现"。

> **Takeaway**：本文以质性 + 问卷 + 焦点小组 + 概念原型展示了"应急车 AR-HUD"的系统设计框架。它为 AR-HUD 行人标注综述贡献了三方面证据：① 驾驶员普遍处于高分心环境（90% 听音乐、60% 读短信）；② 全风挡 AR + V2V/V2X 是必要的工程方向；③ "EV-to-CV"启发"V2P"双向预警，可与可穿戴 AR 行人预警（idx 10）形成闭环。
