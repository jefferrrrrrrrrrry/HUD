## 一、研究背景与问题

### 1.1 领域现状
- 行人死亡在欧洲与日本都是首要课题：日本交通事故死亡 5,744 人中 **行人占 33.8%**（Fig. 1，ITARDA 2007），其余为汽车驾驶员 27.0%、自行车 13.0%、摩托车 9.7%、机动自行车 8.2%、乘客 8.1%。
- 行人检测的传感器手段（引 Gandhi & Trivedi 2007 综述）：立体相机、单目相机、红外相机、LIDAR。摄像头视野宽、分辨率高，能通过图像处理识别对象属性，但**算法复杂、算力开销大、测距不准**；LIDAR 不适合识别属性，但测距准确。**故摄像头 + 雷达融合是获得高可靠性的可行路径**。
- **本文的关键场景选择依据**：日本事故数据显示 **50% 的行人事故发生在斑马线附近，且其中多数为车辆直行**（Fig. 2，ITARDA 2007；原文 Fig. 1 给出细分：斑马线 19,678 起、斑马线附近 2,467 起、人行天桥附近 272 起、其他地点 18,790 起）。因此本文**只聚焦「车辆接近有行人的斑马线」这一场景**，以获得高鲁棒性、低误报率与低成本实现。

### 1.2 研究缺口
- 论文明确批评既有预警系统（引 Ito & Inagaki 2007）只用 **TTC（Time-to-Collision）** 这一简单指标作为报警判据：**「TTC 是考虑两个同向物体之间相对速度的指标，因此当物体从横向接近本车时，TTC 可能不适合表征风险。」**
- 另一类系统（引 Takimoto 2008）只基于**行人当前的纵向位置**估计碰撞风险，**未把行人的横向位置纳入考虑**，因此会给出不恰当的报警。
- → 研究缺口：需要一个把 **TTC 与行人位置预测相结合**的风险估计方法。

### 1.3 核心研究问题
1. 如何用单目相机检测斑马线（利用交比不变性），并与毫米波雷达融合以推断「斑马线上/附近的移动物体即为行人」？
2. 如何把 TTC 与行人预测位置结合，形成分级的视觉 + 听觉预警策略？

## 二、研究方法

### 2.1 被试与样本
**论文未明确报告**——本文为系统开发与实车原理验证（proof of principle），无人类被试实验，仅用木偶（puppet）代替真实行人进行安全验证。

### 2.2 实验设计（系统验证条件）
- 无自变量/因变量的实验设计；为单次功能验证试验。
- 验证条件（第 IV 节）：
  - 试验车**以恒定 20 km/h 垂直于斑马线行驶**；
  - **当 TTC（T_tc）低于 3.0 s 时，行人开始在斑马线上行走**；
  - **试验车不减速**；
  - 为保证安全，**用木偶替代真实行人**。
- 输出验证：显示器上的人工交通灯从黄变红；木偶相对本车的轨迹进入感兴趣区（预警区）。

### 2.3 实验材料与设备
- **试验车传感器（Fig. 3）**：Continental **ARS300 毫米波雷达** + Continental **CSF200 单目 CMOS 相机** + PC + 传感器簇（提供车速与横摆角速度）。
- **77 GHz 毫米波雷达双量程**：
  - 远距扫描：**测量角 18°，探测距离 200 m**；
  - 近距扫描：**测量角 56°，探测距离 60 m**；
  - 雷达内置目标检测与跟踪算法：分割特征点并用**卡尔曼滤波**跟踪输出位置数据；可获得被检目标的**位置与相对速度**；数据经 CAN 总线进入 PC 并可实时监视。
- **单目相机**：**视场 42°（水平）× 26°（垂直）**，分辨率 **752 × 480 像素**，**刷新率 40 ms（=25 Hz）**。
- **车内显示器**：红/黄/绿三色指示灯 + 文字消息。

### 2.4 任务与流程（三个算法模块，Fig. 4）
1. **斑马线检测算法**：利用**四共线点的交比（cross ratio）在透视投影下不变**这一性质。
   - 交比公式（Eq. 1）：`[abcd] = (ac · bd) / (bc · ad)`，其中 `ab` 表示点 a 与点 b 之间的距离。
   - 流程（Fig. 6）：相机图像 → 自动二值化 + Canny 边缘检测 → 两输出取逻辑与（减少路面阴影导致的误差）→ 垂直边缘按「暗→亮」与「亮→暗」分为两类 → 利用斑马线的**周期性**（检查同一图像高度上的边界数量与两边缘间宽度）缩减候选 → 计算四点交比 → 若三对边缘的计算结果符合斑马线交比则判为斑马线 → 用前序帧验证。
   - 假设：车辆直行，故取图像中**同一垂直高度**的四点 a、b、c、d。
2. **传感器融合算法**（Fig. 7、Fig. 8）：
   - 假设：车辆直行且**车辆方向垂直于斑马线**。
   - 步骤 1：把相机图像中斑马线边界的像素坐标 (u, v) 投影到雷达的鸟瞰坐标系 (X_r, Y_r, Z_r)，用 3×4 透视投影矩阵（Eq. 2，元素 p₁₁…p₃₄）；计算中 **Z_r 设为常数，对应传感器相对路面的高度**；矩阵系数由**最小二乘法**基于 **78 个不同位置**的标定数据确定。
   - 步骤 2：把「位于斑马线上或附近」的物体选为行人候选；**斑马线区域向两侧各外扩 1 米的余量（margin of 1 meter at each side）**，以检出斑马线邻近的行人。
   - 步骤 3：把候选的雷达数据 (X, Z) 反投影回相机坐标 (u, v)，把像素角点连成矩形（宽 W、高 H）作为 ROI。论文说明：若有基于外观的行人检测算法可用，可只在这些候选矩形内运行以降低算力开销；**但本文未包含该步，而是直接用毫米波雷达的移动物体数据**。
3. **预警算法**：见第三节。

## 三、关键指标与测量

### 3.1 运动学公式（原文抄录）
本文的核心创新是**用「本车到达行人运动轴所需的预测时间 T_p」替代传统 TTC**，并据此预测行人位置。

三条假设：
- 行人与本车均保持**恒定速度**（V_ped = const，V_car = const）；
- 本车直行且**方向垂直于斑马线**（Y_car = 0）；
- 行人沿上述运动轴以**恒定平均步行速度**移动（Ẋ_ped = const）。

**预测时间（Eq. 3）**：
```
T_p(t) = ( X_ped(t) − X_car(t) ) / V_car
```

**行人预测位置（Eq. 4）**：
```
Y_ped( t + T_p(t) ) = Y_ped(t) + V_ped · T_p(t)
```
其中 `X_ped(t) − X_car(t)` 与 `Y_ped(t)` 由毫米波雷达测得；**行人横穿速度 V_ped 由横向位置 Y_ped 的微分求得，并用滑动平均滤波器（moving average filter）对微分信号做平滑预处理**。

**感兴趣区（预警区）纵向上边界**（Fig. 10、Fig. 13）：
```
R_x = T_tc · V_car      （其中 T_tc_max = 4.0 s）
```
即 `X_max = T_tc_max × V_car`，**上边界与车速成正比**。

### 3.2 时间类指标
| 指标 | 定义/取值 |
|---|---|
| T_tc | 设定行人检测纵向范围的参数，**等价于 time-to-collision** |
| **T_tc_max = 4.0 s** | 感兴趣区（检测/预警区）的纵向上边界常数 |
| **危险等级分档 = 每 1.0 s 一级** | 可视化的危险区按 **T_tc = 1 / 2 / 3 / 4 s** 分为 4 档（Fig. 10、Fig. 17） |
| **T_tc < 2.0 s → 触发听觉预警** | 视觉红色警告之上叠加听觉警告的阈值 |
| 相机刷新率 | 40 ms |

## 四、主要结果与发现

### 4.1 预警策略（第 III.C 节，原文规则抄录）
显示器颜色与消息按以下规则变化，听觉预警在情境更危急时叠加（Fig. 12、Fig. 13）：
- **(a) 绿色**：未检测到斑马线且未检测到行人；
- **(b) 黄色 + 黄色文字「CROSSWALK DETECTED」**：检测到斑马线，或检测到斑马线附近的静止物体；
- **(c) 红色 + 红色文字「CROSSWALK OCCUPIED」**：检测到斑马线**且**斑马线上有移动物体，**且预测位置在 V_car × T_tc 之内**；
  - **在此基础上，若 T_tc 低于 2.0 s，则向驾驶员发出听觉预警**。

### 4.2 4.0 s 阈值的来源（关键引用链）
原文明确：
> 「车辆与纵向范围 T_tc 之间的比例关系**设为常数 4.0 秒**。该值基于 **Ueda 的报告**，该报告指出**行人保护算法的预警在 time-to-collision 4.0 秒处是有效的**。」
> 引文 [7]：Ueda S., Takahashi A., Kimata A., Kobari H., "A Study on Effectiveness of the Pedestrian Warning at Inattentive Driving", *JSAE Transactions*, Vol. 38, No. 2, March, pp. 231–236, 2007.

→ **这是「TTC 4 s 为行人预警有效时机」这一论断在本课题文献链中的一级溯源**。注意 Ueda 的研究是针对「**注意力不集中驾驶（inattentive driving）**」条件下的行人预警有效性——这一边界条件在本课题的规范中必须写明。

### 4.3 实车验证结果
- 试验条件：车速恒定 **20 km/h**，垂直接近斑马线；**T_tc < 3.0 s 时**木偶开始在斑马线上行走；车辆不减速。
- 结果：**木偶进入感兴趣区时，显示器上的人工交通灯由黄变红**（Fig. 15、Fig. 16）。
- 木偶相对本车位置的轨迹（Fig. 17，鸟瞰图）**确实进入了感兴趣区（预警区）**，且图中按 `0 < T_tc < 1 s`、`1 < T_tc < 2 s`、`2 < T_tc < 3 s`、`3 < T_tc < 4 s` 四档标记轨迹段。
- 结论：所提出的行人检测与预警系统算法的**有效性（validity）得到验证**。
- **论文未报告**：检出率、误报率、漏检率的定量数值（作者在结论中明确将「公共道路驾驶中的误报率与漏检评估」列为后续工作）。

## 五、对 AR-HUD 行人预警时空设计的启示

### 5.1 时间参数（本课题核心）

**（1）预警时机 / TTC 阈值 —— 本文最重要的可引用参数**
| 层级 | 阈值 | 输出 |
|---|---|---|
| 检测/呈现区上界 | **T_tc = 4.0 s** | 感兴趣区纵向上边界 `R_x = 4.0 × V_car`；黄色「CROSSWALK DETECTED」在此区间内起作用 |
| 视觉红色警告 | 行人预测位置进入 `V_car × T_tc` 内 | 红色 + 「CROSSWALK OCCUPIED」 |
| **听觉预警** | **T_tc < 2.0 s** | 叠加听觉警告 |
- **4.0 s 的出处**：Ueda et al. (2007) 关于**注意力不集中驾驶条件下**行人预警有效性的研究。
- 换算示例（按本文的 R_x = T_tc × V_car）：
  - 20 km/h（5.56 m/s）→ 4 s 上界 = **22.2 m**；2 s = 11.1 m；
  - 40 km/h（11.1 m/s）→ 4 s 上界 = **44.4 m**；2 s = 22.2 m；
  - 50 km/h（13.9 m/s）→ 4 s 上界 = **55.6 m**；2 s = 27.8 m。
  （以上为基于原文公式的换算，原文只给出 20 km/h 的实测。）

**（2）预警提前期与预警时长**
- 提前期：视觉黄色提示最早可在 **TTC 4.0 s**（即距行人 `4 × V_car` 米）出现；听觉预警的提前期为 **2.0 s**。
- **预警持续时长：论文未明确报告**（预警是状态驱动的——只要条件满足即持续显示，条件解除即回退到低等级）。

**（3）分级预警的时序结构与级间间隔（本文的独特贡献）**
- **三级视觉编码**：绿（无斑马线无行人）→ 黄（有斑马线 / 斑马线附近静止物）→ 红（斑马线被占用且预测位置在预警区内）。
- **双模态升级**：红色视觉 → **T_tc < 2.0 s 时叠加听觉**。
- **危险等级可视化粒度：每 1.0 秒一档**，即 T_tc = 4 / 3 / 2 / 1 s 四段（Fig. 10）。
- → **级间间隔可直接读作 1.0 s；视觉→听觉的升级间隔为 4.0 s − 2.0 s = 2.0 s**（若视觉在最早时机呈现）。

**（4）驾驶员反应时基线**
**论文未明确报告**（无人类被试实验）。本文只承接了 Ueda (2007) 关于 4 s 报警有效性的结论，未自行测量反应时。

**（5）减速度阈值 / AEB 触发时刻 / 制动反应时**
**论文未明确报告**——本系统只做预警（visual + auditory warning），不含自动制动或制动辅助，因此无 AEB 触发时刻、无减速度阈值（DCA / required deceleration）、无制动反应时数据。

**（6）运动学公式（可直接抄入规范）**
```
T_p(t) = ( X_ped(t) − X_car(t) ) / V_car                    （预测时间）
Y_ped( t + T_p(t) ) = Y_ped(t) + V_ped · T_p(t)             （行人预测横向位置）
R_x = T_tc · V_car,  T_tc_max = 4.0 s                       （预警区纵向上界）
[abcd] = (ac · bd) / (bc · ad)                              （斑马线检测的交比）
```

### 5.2 空间参数
- **空间参照系**：本文的核心是**鸟瞰（bird's eye view）平面上的「危险区（hazardous region）」**——这是一个**贴地水平面**的空间表达（Fig. 10、Fig. 17），按 T_tc 分为 4 个 1 s 宽的带状区。这与 AR-HUD 中「贴地水平面投影」的空间参照系天然同构。
- **横向覆盖范围**：斑马线区域**向两侧各外扩 1 m 的余量**（用于检出斑马线邻近的行人）。Fig. 17 的鸟瞰图横向轴范围为 **−10 m 至 +10 m**，纵向 0–30 m。
- **纵向覆盖范围**：由 `R_x = 4.0 × V_car` 动态确定，**与车速成正比**——这是一个可直接迁移到 AR-HUD 的重要原则：**标注/预警区的纵向深度应随车速动态伸缩，而非固定米数**。
- **传感器视场（约束标注可用范围）**：
  - 相机 **42°（H）× 26°（V）**，752×480 px，40 ms 刷新；
  - 雷达远距 **18° / 200 m**，近距 **56° / 60 m**。
  - → 融合后有效横向视场受限于相机 42°；这构成 AR-HUD 贴合式标注在横向上的硬边界。
- **颜色编码**：**绿 / 黄 / 红**三级交通灯隐喻 + 文字消息（"CROSSWALK DETECTED" / "CROSSWALK OCCUPIED"）。作者在结论中强调该设计的优点是「**对驾驶员也容易理解（easy to understand for the driver）**」。
- **呈现位置**：车内座舱显示器（on-cabin display），**非 HUD**。论文未报告图形形态、透明度、闪烁频率、占空比。

### 5.3 可直接写入设计规范的条目
1. **若**以「注意力不集中的驾驶员」为设计对象，**则**行人预警的最早呈现时机可取 **TTC = 4.0 s**（出处：本文第 III.C 节，p. 358，引 Ueda et al. 2007）。
2. **若**采用分级预警，**则**视觉级别可按 **每 1.0 s 一档（TTC 4 / 3 / 2 / 1 s）** 编码危险等级；**听觉（或更强模态）在 TTC < 2.0 s 时叠加**。（第 III.C 节，p. 358）
3. **若** AR-HUD 需要划定「贴地水平面」的危险区，**则**其纵向深度应按 `R_x = T_tc_max × V_car` **随车速动态伸缩**，而非固定米数；T_tc_max 取 4.0 s。（Fig. 10，p. 358）
4. **若**目标是横向冲入的行人，**则不应仅用 TTC 判据**——TTC 只考虑同向相对速度，横向接近时不适用；应改用「本车到达行人运动轴的预测时间 T_p」并据此外推行人横向预测位置（Eq. 3、Eq. 4）。（第 III.C 节，p. 358）
5. **若**限定在斑马线场景，**则**行人候选区应把斑马线**向两侧各外扩 1 m**，以覆盖斑马线邻近的行人。（第 III.B 节步骤 2，p. 357）
6. **若**采用三级颜色编码，**则** 绿=无风险 / 黄=检测到斑马线或静止物 / 红=斑马线被占用且预测位置在预警区内，配合明确文字消息，可获得「对驾驶员易于理解」的语义。（第 III.C 节 + 第 V 节结论）
7. **若**用行人横向速度做预测，**则**必须对横向位置的微分信号做**滑动平均滤波**平滑处理，否则噪声会污染预测位置。（第 III.C 节，p. 358）

## 六、本文局限性与未来工作

作者自陈与可识别的局限：
1. **场景高度受限**：整个方法建立在「**斑马线附近 + 车辆直行 + 车辆方向垂直于斑马线**」三重假设上。斑马线检测本身也假设车辆直行（取同一图像高度的四点）。非斑马线场景、弯道、斜交路口均不适用。作者把这一限制同时作为优点（高鲁棒性、低误报、低成本）来论证。
2. **行人判定是间接的**：「沿斑马线移动的物体在特定情形下可推断为行人」——**没有做基于外观的行人分类**。论文明确指出「若有基于外观的行人算法可用，可在候选矩形内运行以降低算力」，但本文未包含。
3. **恒速假设**：行人与本车都假设恒速；行人以「恒定平均步行速度」移动。行人突然加速、停顿、折返均未建模。
4. **验证极弱**：仅**一次**试验，**用木偶替代真实行人**，车速单一（20 km/h），车辆不减速。**未报告检出率、误报率、漏检率、系统延迟**。
5. **无人因验证**：完全没有驾驶员被试实验；4.0 s 与 2.0 s 两个阈值分别来自外部文献引用与作者设定，**未在本文中验证其对驾驶员反应的实际效果**。
6. **未来工作（第 V 节）**：用同一试验装置在**公共道路**上做进一步研究，并**评估真实世界驾驶中的误报率与漏检**。

## 七、与本课题的关联与引用建议

### 7.1 可用于论文哪一章
- **时间参数章**：本文是「**TTC 4.0 s 作为行人预警有效时机**」在本课题文献链中的**一级引用源与溯源节点**（→ Ueda et al. 2007，JSAE Transactions，针对注意力不集中驾驶）。同时提供了「视觉 4 s / 听觉 2 s」的双级阈值与「每 1 s 一档」的分级粒度。
- **时序结构章**：三级视觉 + 双模态升级的完整规则，是一个可直接对照的分级预警规范样本。
- **空间参数章**：`R_x = T_tc × V_car` 的**车速自适应纵向深度**原则，可直接迁移到 AR-HUD 贴地水平面标注区的设计；鸟瞰危险带（4 档 × 1 s）的可视化形式也可直接借用为 AR-HUD 的贴地图形。
- **算法章**：交比不变量斑马线检测 + 相机-雷达透视投影融合（78 点最小二乘标定）+ 基于 T_p 的行人位置预测，可作为「AR-HUD 标注需要的感知前端」的实现参考。
- **文献综述章**：本文对「TTC 不适用于横向接近目标」的批评，是支持本课题采用「预测位置 / 贴合式空间标注」而非单纯 TTC 阈值的重要论据。

### 7.2 与已收录文献的一致与冲突

**一致之处**
- 与 `70_2016_Kang`（听觉行人预警 TTC 2 s vs 4 s）高度一致：本文正是把 **4 s 用于视觉呈现、2 s 用于听觉报警**——恰好对应 Kang 比较的两个时机。本文的分工方案（4 s 视觉、2 s 听觉）为 Kang 的「哪个更优」提供了一个**职能分离**的解答：两者不是竞争关系，而是**不同模态在时间轴上的分工**。
- 与 `81_2016_Phan` 的空间思想一致：Phan 用两级（早期贴合边界框 → 临界期非贴合面板），本文用两级（早期视觉分级 → 临界期听觉），都是「早期低强度引导注意 → 临界期高强度强制行动」的架构。
- 与 `12_2024_边扬`（网联 HUD 行人过街预警）、`38_2022_Kim`（V2X 路侧 P2CWS）一致：都聚焦「行人过街/斑马线」这一最高频场景。
- 与 `99_2014_Takada`（DCA）一致：都批评单纯 TTC 判据的不足。但两者提出的替代方案不同（见冲突）。

**冲突之处（必须显式指出）**
1. **与 `81_2016_Phan` 在 TTC 阈值上的冲突**：Phan 的 critical TTC 上界为 **2.0 s**（对应 90% 人群），并明确「响应时越大越烦人、绩效越差」；本文把 **4.0 s** 作为呈现上界。
   - 边界条件差异：① **模态与强度不同**——本文 4 s 处只是**黄色被动信息提示**（"CROSSWALK DETECTED"，属于「告知有斑马线」而非「有碰撞风险」），强度极低，因此烦扰风险小；Phan 的 2 s 是**黄色强制性警告面板**。② **驾驶员状态不同**——本文的 4 s 依据 Ueda (2007) 是针对**注意力不集中驾驶**；Phan 的分布是针对一般人群的响应时。
   - **调和结论**：**信息强度与预警时机成反比**——TTC 4 s 处只宜放「低强度环境/情境信息」（有斑马线、有行人存在），TTC 2 s 处才放「高强度行动要求」（制动）。这条原则应写入设计规范。
2. **与 `84_2022_Char` 的冲突**：Char 的 180 人模拟器实验中被试**压倒性抱怨 1.7 s 与 2 s 太晚，要求更早**，仿真最优点在 **2.6 s**；而本文把听觉预警放在 **2.0 s**。
   - 可能原因：本文有 **4 s 处的黄色视觉前置提示**，驾驶员在听觉预警到来前已被「预热」；Char 的 FCW 是**无前置的单级报警**，突然出现在 1.7/2 s 自然显得太晚。
   - → 这进一步支持上述「分级 + 强度递增」的架构，并说明**单级报警的时机需求（>2.6 s）显著早于分级报警末级的时机需求（2.0 s）**。
3. **与 `99_2014_Takada`（DCA）在「TTC 替代指标」上的路线冲突**：两文都认为 TTC 不足，但替代方案不同——Takada 用**所需减速度（DCA/PDCA）**这一动力学量，本文用**预测时间 T_p + 行人预测位置**这一运动学量。
   - 适用边界：Takada 面向**纵向前车**（同向），DCA 能表达制动可行性；本文面向**横向冲入的行人**，T_p 能表达空间交汇。→ 规范中应按目标运动方向选择指标：**纵向目标用 DCA，横向目标用 T_p / 预测位置**。这是本课题可以贡献的整合结论。
4. **与 `09_2025_叶明慧`「预警图形持续 3 s」的差异**：本文预警为**状态驱动、无固定时长**；且叶明慧发现「行人预警不宜用单一近地水平投影」，而本文的危险区正是**贴地水平面的带状区**。
   - 需注意：本文的贴地危险区是显示在**车内平面显示器上的鸟瞰图**，不是 AR-HUD 的贴地叠加，二者的视觉几何完全不同，因此不构成直接冲突；但若要把本文的鸟瞰危险带直接搬到 AR-HUD 贴地面上，需先解决叶明慧发现的「近地水平投影对横向行人危险的 IB 趋势更高」问题——建议改为**混合面**呈现（贴地危险带 + 垂直面行人标注）。

> **Takeaway**：本文给出「视觉预警上界 TTC 4.0 s（源自 Ueda 2007 对注意力不集中驾驶的研究）+ 听觉预警阈值 TTC 2.0 s + 危险等级每 1.0 s 一档」的完整分级时序，并证明横向行人应用预测时间 `T_p = (X_ped − X_car)/V_car` 而非 TTC，预警区纵向深度按 `R_x = 4.0 × V_car` 随车速伸缩。
