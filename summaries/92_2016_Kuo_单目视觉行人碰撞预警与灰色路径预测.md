## 一、研究背景与问题

### 1.1 领域现状
计算机视觉在 ADAS 目标检测中广泛应用。论文综述四类既有工作及其缺陷：
- **Y.C. Lin et al.**：形态学 + 角点检测 + 逆透视映射（IPM）做泊车辅助障碍检测，**计算复杂度低，但只能检测静止物体**。
- **C.G. Keller & T. Dang（2011, IEEE T-ITS 12(4)）**：行人主动安全系统，在特定场景可自动介入制动；用序列立体图像重建 3D 道路场景与 3D 运动场（称 **6-D vision**），可获取并跟踪目标位置。**但算法计算量巨大，难以实现（hard to be implemented）**。
- **C.T. Hong et al.**：车周四摄像头构建鸟瞰视图 + 光流 + IPM 检测车周物体；改善了转弯时车内外侧光流不一致的问题。**但仅适用于基于阿克曼转向几何（Ackermann Steering Geometry）设计的车辆**。
- 作者前作 **Kuo, Yang & Yen (2012, Computers and Mathematics with Applications 64, pp. 1311–1323)**：Haar-like 特征 + 协方差矩阵描述子的**两层级联分类器**行人检测。

### 1.2 研究缺口
- 立体视觉的**硬件成本**与目标检测算法的**计算复杂度**是落地障碍。
- → 本文动机：**仅用单目相机 + 级联检测算法**实现行人碰撞预警，通过限定在 ROI 内计算运动矢量，**消除立体视觉的耗时计算**。

### 1.3 核心研究问题
如何仅凭单目相机，在低算力条件下完成：① 行人检测；② 行人运动矢量估计；③ 行人未来行走路径预测与碰撞点/碰撞时间计算？

### 2.4 任务与流程（三个模块）

**（1）行人检测**（沿用作者前作 [4]）
- 两层级联分类器：前端用 **Haar-like 特征**快速筛选可能存在行人的候选区；后端用**协方差矩阵描述子**精确判定候选区内是否为行人。
- 通过两层则用矩形框（oblong）标记（Fig. 2）。

**（2）行人运动矢量估计**（仅在 ROI 即标记矩形内执行，以提升计算效率）
- **Harris 角点检测**（Eq. 1）提取行人轮廓特征：
  ```
  G(x, y) = ΣΣ w(u,v) · [ Iₓ(u,v)  I_y(u,v) ] · [Δx, Δy]ᵀ 的平方和
          = [Δx  Δy] A [Δx  Δy]ᵀ
  其中 A = ΣΣ w(u,v) · [ Iₓ²    IₓI_y ]
                        [ IₓI_y  I_y² ]
  ```
  - `G(x,y)` 等于 **0°, 45°, 90°, 135°, 180°, 225°, 270°, 315° 共 8 个方向**的微分误差平方和；
  - `(u, v)` 为计算范围，**通常取 3×3 方形区域**；
  - Δx、Δy 为该范围内 x、y 方向位移；w 为高斯窗；I 为 (x,y) 处灰度值，Iₓ、I_y 为 x、y 方向微分值；
  - **若矩阵 A 的特征值 λᵢ 彼此接近，则 (x,y) 判为角点**。
- **改进的 Lucas-Kanade 光流法**（Eq. 2–4）估计运动矢量：
  ```
  I(x, y, t) = I(x + u, y + v, t + 1)              （亮度恒定假设，Eq. 2）
  [Iₓ  I_y] · [u  v]ᵀ + I_t = 0                    （Taylor 展开，Eq. 3）
  d = [u v]ᵀ = ( [ ΣIₓIₓ  ΣIₓI_y ]  )⁻¹ · ( [ −ΣIₓI_t ] )   （Eq. 4）
                 [ ΣIₓI_y ΣI_yI_y ]                  [ −ΣI_yI_t ]
  ```
  - 假设 LK 光流具有**空间一致性（spatial coherence）**：(x,y) 周围 **n×n 邻域**以相同方向与速度运动；
  - d 表示 8 个不同方向上的运动矢量。

**（3）碰撞预测**
- **行人位置计算**（Eq. 5）：把检测矩形**分为头部、躯干、足部三区**（Fig. 3a）。理由：行人运动时**手/脚变化剧烈，不适合用于估计运动矢量**。因此：
  - **用头部区在连续帧中的变化估计运动矢量**；
  - **用足部在图像上的位置代表行人位置**（Fig. 3b，黄线标出）。
  ```
  m(x, y) = ( Σᵢ₌₁^{n_h} headᵢ(x) / n_h ,  Σᵢ₌₁^{n_f} footᵢ(y) / n_f )
  ```
  其中 n_h、n_f 分别为头部区与足部区的角点数。
  - 流程：① 矩形分三区；② 对头部与足部区角点用光流法算运动矢量；③ **依据角点光流区分并剔除属于背景的角点**；④ 用 Eq. 5 计算行人位置。
- **危险区（hazardous zone）定义**（Fig. 4）：定义为「车辆行驶路线即将驶入的区域」。危险发生于两种情形：① 行人**将要**出现在危险区内；② 行人**停留**在危险区内。
  - 设定依据「一般市区道路与一般车辆尺寸」；相机装在风挡中央。
  - **1.5 米线左侧记为 D_L，右侧记为 D_R**。
- **行人未来路径预测：灰色理论（Grey theory）**。选用理由：灰色理论具有「**新信息优先（priority of new information）**」与「**最小信息探索不确定性**」的性质，使预测对行人后续路径更敏感。
  - GM(1,1) 灰色微分方程（Eq. 6）：
    ```
    dx⁽¹⁾/dt + a·x⁽¹⁾ = b
    ```
    其中 a 为发展函数系数，b 为控制变量，x 为变量序列。GM(h, N) 中 h 为微分阶数、N 为变量数。
  - 用光流得到的运动矢量 d = [u v]ᵀ 预测行人下一位置（Eq. 7）：
    ```
    (P_{x+f}, P_{y+f}) = ( Pₓ + Δu₁ + … + Δu_f ,  P_y + Δv₁ + … + Δv_f )
    ```
    其中 (Pₓ, P_y) 为行人当前位置，`f·ΔT` 为未来时刻，Δuᵢ、Δvᵢ 为时刻 `i·ΔT` 与 `(i−1)·ΔT` 之间运动矢量的差值。
- **碰撞点计算**：若行人将穿越危险区范围，则用当前位置 (Pₓ, P_y) 与 `f·ΔT` 后的未来位置 (P_{x+f}, P_{y+f}) 建立直线方程，用 **克拉默法则（Cramer's rule）** 求该直线与危险区边界的交点 (x_c, y_c)（Fig. 6）。
- 依据行人位置与运动矢量，定义 **6 种未来运动类型**（Fig. 5，绿点=行人位置，蓝矢量=运动方向）。

## 三、关键指标与测量
- 空间指标：行人位置 (x, y)（米）；碰撞点位置 (x, y)（米）。
- **时间指标（本文唯一的时间量）**：
  - **行人到达碰撞点的时间（time that pedestrian to reach the point of collision）**；
  - **车辆到达碰撞点的时间（time that vehicle to reach the point of collision）**。
- 论文**未定义 TTC 阈值、未定义预警触发条件的时间判据**——仅计算「碰撞可能性」，未给出「何时报警」。

## 四、主要结果与发现

### 4.1 检测与运动矢量
- 角点检测结果（Fig. 7）与运动矢量结果（Fig. 8）以图示给出，**无定量指标**（无检出率、精度、召回率、处理帧率）。

### 4.2 实车实测结果（Fig. 9，原文数值抄录）
台湾市区道路白天测试，一组「估计值 vs 实测值」对照：

| 量 | 估计值 | 实际值 | 误差 |
|---|---|---|---|
| 行人距离 (x, y) | (1.42 m, 4.37 m) | (1.55 m, 4.52 m) | Δx = 0.13 m，Δy = 0.15 m |
| 碰撞点距离 (x, y) | (−1.91 m, 6.04 m) | (−2.03 m, 6.08 m) | Δx = 0.12 m，Δy = 0.04 m |
| **行人到达碰撞点的时间** | **5.32 s** | **5.58 s** | **0.26 s（低估 4.7%）** |
| **车辆到达碰撞点的时间** | **0.78 s** | **0.78 s** | **0（完全一致）** |

- 注意这组数据的**含义**：车辆将在 **0.78 s** 后到达碰撞点，而行人需 **5.32–5.58 s** 才到达该点——**即本例中实际不会发生碰撞**（车先通过）。论文未就此展开讨论，也未说明系统在这种时序差下是否/如何报警。

### 4.3 结论性陈述
- 系统能**同时处理多个行人**并正确计算碰撞可能性（论文断言，未给出量化证据）。
- 并行架构使三个功能模块可并行处理，「**这将使系统达成实时处理应用**」——注意原文用的是将来时（will enable），即**尚未验证实时性**，未报告帧率或延迟。

## 五、对 AR-HUD 行人预警时空设计的启示

### 5.1 时间参数（本课题核心）

**（1）预警时机 / TTC 阈值**
- **论文未明确报告任何 TTC 阈值或预警触发时机。**本文只输出「行人到达碰撞点时间」与「车辆到达碰撞点时间」两个量，**未定义在何种时间差下触发预警**。

**（2）预警提前期与预警时长**
- **论文未明确报告。**本文无 HMI 设计（无视觉/听觉/触觉输出的任何描述），仅止于「可提醒驾驶员注意行人（It can remind the driver to caution pedestrians）」这一定性表述。

**（3）驾驶员反应时基线 / 制动反应时**
- **论文未明确报告**（无人类被试）。

**（4）AEB 触发时刻 / 减速度阈值（DCA、required deceleration）**
- **论文未明确报告**——本系统只做碰撞预测，不含自动制动，无任何减速度相关参数。

**（5）分级预警与级间间隔**
- **论文未明确报告**——无分级设计。

**（6）本文唯一可用的时间量：双侧到达时间（TTA, time-to-arrival）范式**
- 实测样例：**行人到达碰撞点 5.32 s（估计）/ 5.58 s（实际）；车辆到达碰撞点 0.78 s（估计=实际）**。
- 估计精度：行人 TTA 误差 **0.26 s**；车辆 TTA 误差 **0**；位置误差 **0.04–0.15 m**。
- → **这是本文对本课题唯一的可量化贡献**：它给出了「**双侧到达时间比较（行人 TTA vs 车辆 TTA）**」这一风险判据的实现精度基准（TTA 误差量级 0.3 s、位置误差量级 0.15 m）。这一精度决定了 AR-HUD 贴合式标注的时间与空间可信度上限。

**（7）运动学/预测公式（可抄入规范的预测方法）**
```
m(x, y) = ( Σ headᵢ(x)/n_h ,  Σ footᵢ(y)/n_f )                    （行人位置：头部估运动、足部定位）
(P_{x+f}, P_{y+f}) = ( Pₓ + Σ_{i=1..f} Δuᵢ ,  P_y + Σ_{i=1..f} Δvᵢ )   （灰色预测的未来位置）
dx⁽¹⁾/dt + a·x⁽¹⁾ = b                                              （GM(1,1)）
```
- 预测步长为 `f·ΔT`，其中 ΔT 为帧间隔——**论文未报告 ΔT 的具体值，也未报告 f 的取值**，因此**预测时域（prediction horizon）无从量化**。这是本文在时间参数上最关键的缺失。

### 5.2 空间参数
- **危险区（hazardous zone）几何（本文唯一明确的空间参数）**：
  - 定义为「车辆行驶路线即将驶入的区域」，依据「一般市区道路与一般车辆尺寸」设定；
  - **以 1.5 米线为界，左侧记 D_L、右侧记 D_R**（Fig. 4）。这是一个**贴地水平面的矩形/梯形走廊**表达。
  - 危险判据：行人**将要进入**或**停留在**危险区内。
- **实测的空间尺度**：行人位于 (1.55 m, 4.52 m)；碰撞点位于 (−2.03 m, 6.08 m)。→ 有效工作距离在**车前 4–6 m、横向 ±2 m** 量级（仅此一组样例）。
- **相机安装参数（约束标注的空间标定）**：焦距 **29 mm**，分辨率 **640×360**，**安装高度 120 cm**，**俯仰角 1°**，装在**前风挡中央**。
  - 论文**未报告相机视场角（FOV）**——这是空间参数上的重要缺失，无法直接推算标注可覆盖的横向角度。
- **行人的空间分区（可用于 AR-HUD 标注锚点设计）**：检测框分**头部/躯干/足部**三区；**足部位置作为行人的地面锚点**，头部区用于运动估计。
  - → 这一点对 AR-HUD **贴地水平面标注**有直接价值：**足部位置是行人在地平面上的正确锚点**，若把标注锚在检测框中心或头部会产生地面投影偏差。
- **颜色/形态/透明度/闪烁频率/占空比**：**论文未明确报告**（无 HMI 设计）。图示中用矩形框标记行人、绿点标记位置、蓝矢量标记方向，但这些是**算法可视化**而非面向驾驶员的界面设计。

### 5.3 可直接写入设计规范的条目
1. **若** AR-HUD 需在贴地水平面锚定行人标注，**则**应以**行人足部在图像中的位置**作为地面锚点，而以**头部区的帧间变化**估计运动矢量（因手/脚摆动剧烈不适合估计运动）。（第 II.C.1 节，Fig. 3，p. 741）
2. **若**要定义前向危险走廊，**则**可按「车辆即将驶入的路线区域、以 1.5 m 线划分左右（D_L / D_R）」设定，并把「行人将进入」与「行人停留其中」都判为危险。（第 II.C.1–2 节，Fig. 4，p. 741）
3. **若**风险判据需覆盖横向冲入行人，**则**应比较**行人到达碰撞点的时间**与**车辆到达碰撞点的时间**（双侧 TTA），而非单一 TTC；本文实测该判据的精度为 **TTA 误差 ≤ 0.26 s、位置误差 ≤ 0.15 m**。（第 III 节，Fig. 9，p. 743）
4. **若**行人路径预测需对突变敏感，**则**可用灰色 GM(1,1) 模型（新信息优先特性），输入为光流运动矢量差值序列。（第 II.C.2 节，Eq. 6–7，p. 741–742）
5. **若**要控制单目方案的算力，**则**把角点检测与光流计算**限制在行人检测框（ROI）内**，并用三模块并行架构。（第 II.B、IV 节）
6. **告知性条目（负面证据）**：本文虽题为「Pedestrian Collision Warning」，**却完全没有定义预警时机、预警模态、预警时长与分级结构**。这说明「PCW 算法文献」与「PCW 人机界面文献」之间存在显著断层——**算法侧提供的是「碰撞点与到达时间」，而 HMI 侧需要的是「阈值与时序」，二者之间的映射需由本课题补齐**。

## 七、与本课题的关联与引用建议

### 7.1 可用于论文哪一章
- **算法/感知前端章**：可作为「低成本单目行人碰撞预测」的一个实现参考，尤其是**足部锚点**与**头部运动估计**的分区策略——这对 AR-HUD 贴地标注的锚点设计有直接价值。
- **文献综述章（用于论证研究缺口）**：本文是**「算法侧文献不提供预警时机参数」这一断层的典型代表**，可用来论证本课题「补齐算法输出到 HMI 时序规范之间映射」的必要性。
- **不宜用于时间参数章的主表**：本文不提供任何 TTC 阈值或时机参数，只能作为「双侧 TTA 判据的实现精度基准」被引用（TTA 误差 ≤ 0.26 s，位置误差 ≤ 0.15 m）。

### 7.2 与已收录文献的一致与冲突

**一致之处**
- 与 `90_2010_Suzuki` 在**风险判据的路线上高度一致**：两文都认为单一 TTC 不适用于横向接近的行人，都改用「行人与车辆分别到达交汇点的时间」这一双侧比较范式。Suzuki 的 `T_p = (X_ped − X_car)/V_car` 与本文的「行人 TTA vs 车辆 TTA」是同一思想的两种实现。
- 与 `37_2016_Jung`（CNN 语义分割 PCW）、`17_2023_Roh`（深度学习行人与个人移动工具 AR-HUD）同属「感知算法 + PCW」文献族；本文属该族中较早、较轻量的单目方案。
- 与 `99_2014_Takada` 一致：都不满足于单纯 TTC。

**冲突之处（必须显式指出）**
1. **与本课题主线（时空设计规范）的根本性缺口**：本文**没有任何预警时机参数**，与 `70_2016_Kang`（TTC 2 s / 4 s）、`90_2010_Suzuki`（4 s / 2 s）、`81_2016_Phan`（1.0/1.6/2.0 s）、`84_2022_Char`（1.7/2/2.3/2.6 s）等文献形成**不可比**的状态。
   - 这不是数值冲突，而是**层次冲突**：算法文献停留在「能否算出碰撞点」，人因文献关注「何时告诉驾驶员」。→ 本课题应显式指出：**PCW 算法性能（本文误差 0.26 s / 0.15 m）构成预警时机设计的精度下限**——若感知误差已达 0.26 s，则把预警时机的分辨率设计到 0.3 s 以下（如 Char 比较的 1.7 s vs 2.0 s，相差 0.3 s）在工程上是不可靠的。**这是本文对本课题最有价值的间接贡献。**
2. **与 `09_2025_叶明慧`「行人预警不宜用单一近地水平投影」的潜在冲突**：本文的危险区（1.5 m 线划分的贴地走廊）与足部锚点策略，天然导向**贴地水平面**的标注。叶明慧发现水平面在行人场景下的无意视盲（IB）趋势更高。
   - 调和：本文的足部锚点解决的是「**几何正确性**」问题（行人在地平面上的真实位置），叶明慧关注的是「**注意捕获**」问题。二者可并存：**用足部位置确定地面锚点的水平坐标，但图形本身采用混合面（贴地基座 + 垂直面标识）呈现**。
3. **与 Keller & Dang (2011) 的实现取向冲突（论文自陈）**：本文批评 6-D vision 立体视觉「算力巨大、难以实现」，选择单目 + 灰色预测。代价是精度与鲁棒性：本文只有一组样例验证，且无 FOV、无帧率报告。→ 规范中应注明：**若 AR-HUD 需要高精度的贴合式（contact-analog）行人标注，单目 + 灰色预测的 0.15 m 位置误差可能已接近可接受边界**。

> **Takeaway**：本文提供的是单目 PCW 的感知精度基准（行人到达碰撞点时间估计 5.32 s vs 实测 5.58 s，误差 0.26 s；位置误差 ≤ 0.15 m；危险区以 1.5 m 线划分），并给出「足部定位 + 头部估运动」的锚点策略；但**全文未定义任何预警时机、时长或分级阈值**。
