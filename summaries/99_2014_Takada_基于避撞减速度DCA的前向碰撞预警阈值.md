## 一、研究背景与问题

### 1.1 领域现状
- 日本政府《第八次交通安全基本计划》推动 ASV（Advanced Safety Vehicle）。本文聚焦 **FOCWS（Forward Obstacles Collision Warning System，前方障碍物碰撞预警系统）**——即前向碰撞损伤减轻制动系统的预警功能。
- 现有碰撞避免系统用立体相机、激光雷达或毫米波雷达探测障碍物。
- 作者前作序列：
  - Hiraoka et al. (2009a, *Rev. Autom. Eng.* 30(4), pp. 429–437)：首次提出 **DCA（Deceleration for Collision Avoidance）** 作为前方障碍物碰撞风险评价指标；
  - Hiraoka et al. (2009b, 同刊 pp. 439–447)：基于 DCA 的 FOCWS 与模拟器实验；
  - Hiraoka & Takada (2011, *Trans. SICE* 47(11), pp. 534–540)：**改进 DCA**；
  - Hiraoka et al. (2008, 15th ITS World Congress)：情境自适应的 FOCWS 报警时机（本文 TTC 4.0 s 阈值的出处）。

### 1.2 研究缺口
- 前作 [12] 的结果**未能充分澄清 FOCWS 的定量有效性**，也未检验其**负面**影响，因为**没有对照「无 FOCWS」条件**。
- 最初提出 DCA 的论文 [11] 中，DCA 的计算过程假设**后车在驾驶员恒定反应时内做匀速运动**，这会导致：**后车加速时低估风险、减速时高估风险**。
- 前作 [12] 的可视化界面**过于复杂可能造成驾驶员困惑**——有被试反馈：「**我不明白该盯红条还是黄条**」。

### 1.3 核心研究问题
1. 改进 DCA（假设后车在反应时内做**匀加速运动**）后，基于改进 DCA 的 FOCWS 在**前车急减速**情境下能否定量地缩短反应时并减少碰撞？
2. 改进后的可视化界面能否降低困惑？
3. 与**基于 TTC 的 FOCWS** 相比，被试主观上认为哪种能更恰当地评价碰撞风险、哪种报警时机更恰当？

## 二、研究方法

### 2.1 被试与样本
- **N = 16**：**12 男 4 女**，年龄 **20–36 岁（平均 26.1 岁）**。
- 作者在结论中自陈「16 人不足以完全验证有效性」，计划追加实验。

### 2.2 实验设计
- **被试内设计**，单因素 3 水平。
- **自变量：驾驶条件 3 水平**：
  - (a) **w/o 条件**：无 FOCWS；
  - (b) **TTC 条件**：使用基于 TTC 的 FOCWS（TTC-FOCWS）；
  - (c) **DCA 条件**：使用基于改进 DCA 的 FOCWS（DCA-FOCWS）。
- **因变量**：
  - 碰撞次数（每条件 8 个评价区段，即 8 次急减速）；
  - **brake-on TTC**：驾驶员因前车急减速而踩下刹车瞬间的 TTC 值；
  - **brake-on ODCA**：同一瞬间的 ODCA 值；
  - **Rt1**：从前车开始减速到后车驾驶员踩下刹车的时间间隔（对前车的反应时）；
  - **Rt2**：从 FOCWS 发出碰撞报警到驾驶员踩下刹车的时间间隔（对报警的反应时）；
  - **PDCA > 4.0 m/s² 的累计时长**；
  - 主观问卷 Q.1（1-a、1-b 五级量表；1-c 自由作答）与 Q.2（2-a–2-e 五级量表，−2 = TTC-FOCWS ~ 0 = 都不 ~ +2 = DCA-FOCWS；2-e-2 自由作答）；
  - **DSQ（Driving Style Questionnaire）**（Ishibashi 2002）。
- **统计方法**：单因素 ANOVA + **Shaffer 多重比较检验**（5% 水准）；部分分析用二因素 ANOVA（驾驶条件 × 前车减速模式）。
- **顺序效应控制**：16 名被试分为 **4 组**，实验顺序各不相同。

### 2.3 实验材料与设备
- **固定基座自制驾驶模拟器**（与前作 [12, 14] 相同，Fig. 3）：装 DSP 单元；接口含方向盘、油门踏板、刹车踏板、仪表显示。DSP 上运行 **CarSim RT-Linux**，基于驾驶员输入**实时计算 19 自由度车辆动力学**。
- **三种可视化界面（Fig. 2）**：
  - **前作 DCA-FOCWS（Fig. 2a，本文未使用）**：内侧**黄条**表示 PDCA 值 α_p，外侧**红条**表示 ODCA 值 α_o；条形**垂直伸缩**，**顶端 = 6.0 m/s²，底端 = 0 m/s²**；颜色与伸缩方向按**刺激-反应兼容性（S-R compatibility，Fitts & Seeger 1953）**设计。
  - **本文改进的 DCA-FOCWS（Fig. 2b）**：**中央单条**表示 ODCA 值 α_o，**顶端 6.0 m/s²、底端 0 m/s²**；
    - 条形颜色按后车当前减速度 a_f0 变化：**减速足以避撞（−a_f0 ≥ α_o）时显示浅蓝（light blue）；减速不足（−a_f0 < α_o）时变为橙色（orange）**；
    - **PDCA 超过 4.0 m/s² 时，中央条周围出现黄色边框（yellow frame）**。
  - **TTC-FOCWS（Fig. 2c）**：**橙色条**表示 TTC；**顶端 = 12 s，底端 = 0 s**——刻意设计成使条形伸缩方向与报警阈值线与 DCA-FOCWS 对齐（12 s 的 1/3 = 4 s，恰对应 6.0 m/s² 的 2/3 = 4.0 m/s² 的阈值线位置）。
- **道路与交通**：单向双车道直路，**宽 7 m、长 6 km**。被试驾后车在左车道；前车在其前方；并行车（parallel-running vehicle）在右车道。
- **前车速度设定**：**最大速度 80 km/h**；在评价区段外**随机加减速，幅度 0.1–0.3 G**；每个驾驶条件下前车在全程共**停车 18 次**。
- **并行车速度**：右车道并行车在时刻 t 的速度 = **前车在 t − 1 s 时刻的速度**（即滞后 1 秒跟随前车速度）。

### 2.4 任务与流程
- **主任务指导语（4 条）**：
  1. 在左车道行驶并跟随前车；
  2. 察觉危险时采取恰当的回避行为；
  3. 与前车保持足以防止并行车切入的距离（仪表右缘在车距过大时变黄，追加指示「显示提示时追上前车」）；
  4. 在不干扰驾驶能力的前提下执行心算副任务。
- **副任务（心算）**：**每 2 秒**听到两个 1–9 之间的数字，相加后口头作答。目的是**复现真实驾驶等效的驾驶员工作负荷**。
- **流程**：先练习驾驶熟悉模拟器 → 依 4 组不同顺序完成 3 个条件；每条件驾驶该 6 km 路线 **3 次**；每次含 4 种危险减速模式（Fig. 4）中的 2 种（随机顺序），共设 **8 个评价区段**，每区段含 1 种危险减速模式。
- **系统说明的限制（重要的方法学控制）**：TTC/DCA 条件前只告知「**条形随碰撞可能性升高而向上伸展，风险超过红线时发出碰撞报警**」，**不解释 TTC、DCA 的含义，也不告知最佳使用方法**；被试通过观看自动演示与自主驾驶来熟悉界面。

## 三、关键指标与测量

### 3.1 DCA 定义与完整公式（原文抄录）

**DCA 定义**：DCA [m/s²] 是「后车为避免与前方障碍物（如前车）碰撞所**必需的最小减速度**」。
- **ODCA（overt DCA，显性 DCA）α_o**：假设**前车维持其当前加速度**时的 DCA；
- **PDCA（potential DCA，潜在 DCA）α_p**：假设**前车随时可能急减速**时的 DCA。

**符号（Fig. 1）**：前车以加速度 a_p0 匀加速；后车在驾驶员反应时 T 内以 a_f0 匀加速，反应时 T 后以 a_fT。相对位置 x_r = x_f − x_p（后车在前车后方时为负，车距 = −x_r）。

**反应时 T 的定义（Eq. 2，本文最重要的时间参数之一）**：
```
T = 1.2 s   （当 b_r = 0）
T = 0.2 s   （当 b_r > 0）
```
其中 b_r 为**刹车踏板踩踏程度（0 ≤ b_r ≤ 1）**。
- **1.2 s 的出处**：前作 [12] 中把反应时 T 定为常数 **1.21 s**，因为**模拟器实验揭示全部记录反应时的 90% 都在该值以内**（即 **1.21 s = 反应时分布的 90 百分位**）。
- **0.2 s 的理由**：**驾驶员已经在踩刹车踏板时，反应时会显著小于上述值，故缩短为 0.2 s。**

**反应时内碰撞不可避免的条件（Eq. 1）**：
```
x_r0 + v_r0·T + ½·a_r0·T² < 0
```
含义：**若碰撞将在反应时 T 内发生，则即使 FOCWS 报警，驾驶员也无法避免碰撞。**

**ODCA α_o（Eq. 3）**：分三种情形（0 / −a_f1 / −a_f2），判据为：
```
α_o = 0      当 (a_p0 ≥ 0 且 v_p0 + a_p0·T ≥ v_f0 + a_f0·T) 或 (a_p0 < 0 且 −v_p0/a_p0 < t₁ 且 v_f0 + a_f0·T ≤ 0)
α_o = −a_f1  当 (a_p0 ≥ 0 且 v_p0 + a_p0·T < v_f0 + a_f0·T) 或 (a_p0 < 0 且 T < t₁ < −v_p0/a_p0)
α_o = −a_f2  当 (a_p0 < 0 且 −v_p0/a_p0 < t₁ 且 v_f0 + a_f0·T > 0)
```
其中（Eq. 4–6）：
```
a_f1 = ( v_r0² + 2·a_p0·x_r0 + (2·v_r0 + a_r0·T)·a_f0·T ) / ( x_r0 + 2·v_r0·T + a_r0·T² )          (4)
a_f2 = ( v_f0 + a_f0·T )² / ( 2·x_r0 + 2·v_f0·T + a_f0·T² + v_p0²/a_p0 )                            (5)
t₁   = −( 2·x_r0 + v_r0·T ) / ( a_r0·T + v_r0 )  ≤ −v_p0/a_p0                                       (6)
```

**PDCA α_p**：**基于「前车以 0.6 G（= 5.88 m/s²）的恒定速率突然减速」这一假设**。计算过程与 ODCA 基本相同，差别在于把前车加速度 a_p0 设为：
- **前车前进中（v_p0 > 0）时：a_p0 = −5.88 m/s²**；
- **前车已停止（v_p0 = 0）时：a_p0 = 0 m/s²**。

情形 1（前车前进，Eq. 7）：
```
α_p = 0       当 (v_p0 > 0, v_p0/5.88 < t′₁, v_f0 + a_f0·T ≤ 0)
α_p = −a′_f1  当 (v_p0 > 0, T < t′₁ ≤ v_p0/5.88)
α_p = −a′_f2  当 (v_p0 > 0, v_p0/5.88 < t′₁, v_f0 + a_f0·T > 0)
```
其中 a′_f1、a′_f2、t′₁ 由 Eq. 4、5、6 中把 a_p0 代入 **−5.88 m/s²** 得到。

情形 2（前车停止，Eq. 8）：
```
α_p = 0        当 (v_p0 = 0, a_p0 = 0, v_f0 + a_f0·T ≤ 0)
α_p = −a″_f1   当 (v_p0 = 0, a_p0 = 0, v_f0 + a_f0·T > 0)
```
其中 a″_f1 为把 v_p0 = 0、a_p0 = 0 代入 a_f1 的结果。

**TTC 定义（本文用于对照）**：
```
TTC = −x_r / v_r
```

### 3.2 阈值汇总
| 参数 | 值 | 出处/理由 |
|---|---|---|
| **ODCA 报警触发阈值** | **4.0 m/s²** | 由前作模拟器实验 [12] 确定 |
| **ODCA 报警解除阈值** | **2.0 m/s²** | 「报警持续直到 α_o 降到 2.0 m/s² 以下，**以避免出现极短促的报警**」 |
| **PDCA 黄色边框显示阈值** | **4.0 m/s²** | PDCA 超过该值时中央条周围出现黄框 |
| **TTC 报警触发阈值** | **TTC < 4.0 s** | 由作者前作 [16]（Hiraoka 2008, 15th ITS World Congress）在**同一驾驶模拟器环境**中确定为恰当的报警时机阈值 |
| **PDCA 假设的前车急减速度** | **0.6 G = 5.88 m/s²** | PDCA 定义的前提假设 |
| **驾驶员反应时 T** | **1.2 s（未踩刹车）/ 0.2 s（已踩刹车）** | 1.2 s 源自前作 90 百分位（1.21 s） |
| 可视化条形量程 | ODCA/PDCA：**0–6.0 m/s²**；TTC：**0–12 s** | 使两界面的阈值线位置对齐 |

### 3.3 时间类指标
- **Rt1**：前车减速 → 后车驾驶员踩刹车的时长（对前车的反应时）；
- **Rt2**：FOCWS 报警 → 驾驶员踩刹车的时长（对报警的反应时）。**Rt2 为负值表示驾驶员在报警之前就已踩下刹车**。
- **brake-on TTC / brake-on ODCA**：踩刹车瞬间的 TTC / ODCA 值。
- **PDCA > 4.0 m/s² 的累计时长**（秒）。

## 四、主要结果与发现

### 4.1 碰撞避免（第 4.1 节）
- 每条件共 8 次急减速（模拟追尾）。**单因素 ANOVA：F(2, 30) = 4.33, P < 0.05**；Shaffer 多重比较（5%）：**DCA 条件的碰撞次数显著少于 w/o 与 TTC 条件**。
- **brake-on TTC**：**F(2, 30) = 12.91, P < 0.001**；多重比较（5%）：**DCA 条件的 brake-on TTC 显著大于其他两条件**（即在更早、更安全的 TTC 处就已制动）。
- **brake-on ODCA**：**F(2, 30) = 11.50, P < 0.001**；**DCA 条件的 brake-on ODCA 显著小于其他两条件**（即制动时所需减速度更小，更安全）。
- 二因素 ANOVA（驾驶条件 × 减速模式）：
  - 碰撞次数的交互显著 **F(6, 90) = 3.45, P < 0.01**；brake-on TTC 的交互显著 **F(6, 90) = 3.84, P < 0.01**；
  - 碰撞次数在 **Pattern 1** 上驾驶条件主效应显著 **F(2, 30) = 11.67, P < 0.001**；
  - brake-on TTC 在 **Pattern 1**（**F(2, 30) = 12.08, P < 0.001**）与 **Pattern 3**（**F(2, 30) = 6.20, P < 0.01**）上显著；
  - 多重比较：以上 DCA 条件均显著优于 w/o 与 TTC 条件（5%）。
- **Pattern 1 的机制解释（关键）**：Pattern 1 中，前车加速时后车也跟着加速，**前车在刚达到 80 km/h 后突然急减速**。由于**改进的 DCA 反映了后车当前的加速度**，因此在**后车正在加速的情境下能更早发出碰撞报警**——报警在前车急减速后立即给出，从而缩短了后车驾驶员的反应时并减少碰撞。

### 4.2 反应时（第 4.2 节）
- **Rt1（对前车减速的反应时）**：**DCA 条件略小于其他两条件，但无显著差异**。
- **Rt2（对报警的反应时）**：**DCA 条件明显大于 TTC 条件**。作者解读：**DCA-FOCWS 在被试打算踩刹车之前就已经给出了报警**（即报警足够早）。
  - **TTC 条件下 Pattern 1 的 Rt2 为负值**——意味着**许多被试在 TTC-FOCWS 报警之前就已踩下刹车**（报警太晚）；
  - Pattern 2–4 中也有部分被试在报警之前就打算踩刹车。
- **论文未报告 Rt1、Rt2 的具体秒数**（仅以 Fig. 7a、7b 柱状图呈现，正文只作定性比较）。这是本文在反应时定量上的缺失。

### 4.3 对驾驶行为的影响（第 4.3 节）
- **4 名被试（#3、#8、#11、#15）表现出独特的驾驶行为**：其 **PDCA > 4.0 m/s² 的累计时长在 DCA 条件下显著下降**（Table 1a，抄录，单位秒）：

| 被试 | w/o | TTC | DCA |
|---|---|---|---|
| #3 | 182.0 | 240.2 | 167.9 |
| #8 | 237.8 | 192.1 | 156.4 |
| #11 | 149.7 | 219.8 | 97.5 |
| #15 | 152.4 | 194.4 | 99.2 |
| **均值** | **180.5** | **211.6** | **130.3** |

- 对比：**全体被试的均值为 w/o 207.8 s、TTC 227.9 s、DCA 204.5 s**——即该趋势仅出现在这 4 人身上。
- 这 4 人的碰撞次数也在 DCA 条件下下降（Table 1b）：

| 被试 | w/o | TTC | DCA |
|---|---|---|---|
| #3 | 3 | 0 | 0 |
| #8 | 5 | 5 | 1 |
| #11 | 1 | 1 | 0 |
| #15 | 1 | 2 | 0 |
| **均值** | **2.50** | **2.00** | **0.25** |

- 机制：尽管**没有任何被试被告知如何使用 FOCWS**，这 4 人似乎主动**控制车速以避免黄色边框出现（即保持 PDCA 不超过 4.0 m/s²）**，从而维持了更安全的车距。
- 案例（Fig. 8）：被试 #8 在 DCA 条件的 Pattern 4 中——该模式下**前车以 50 km/h 行驶超过 60 秒后以 0.4 G 减速**——#8 控制车速使黄框不出现。
- 其余 12 名被试（Fig. 9a）：DCA 条件平均碰撞 **1.75 次**，高于上述 4 人的 **0.25 次**，但**两者无统计差异**；这 12 人的 brake-on TTC 与 brake-on ODCA 趋势与全体相同。

### 4.4 主观评价（第 5 节）
- **Q.1-a「所提供的信息有用吗？」**：**DCA-FOCWS 的碰撞报警得分显著高于 TTC-FOCWS**（Fig. 10a）——与 4.2 节 Rt2 在 DCA 条件下更大的定量结果一致。
- **Q.2-a「你感觉到两系统的差异吗？」**：**16 人中 12 人感到差异**（7 人「感到差异」、5 人「感到小的差异」）。
- **Q.2-b（界面易懂度）与 Q.2-e（愿意在真实驾驶中使用）**：**答案两极分化、各占一半**（意见因人而异）。
- **Q.2-c（碰撞风险评价哪个更有效）与 Q.2-d（碰撞报警时机哪个更有效）**：**总体得分为 2（即最大程度偏向 DCA-FOCWS）**——「**相当数量的被试认为 DCA-FOCWS 在碰撞风险评价上更优**」，作者称此结果「somewhat remarkable」。
- **Q.1-b/1-c 自由作答**：
  - 被试 #4、#9、#14：「**我努力让条形保持蓝色**」；
  - 被试 #3、#5、#11、#15：「**黄框出现时，我努力拉开与前车的距离**」；
  - → 说明被试基于 DCA-FOCWS 的信息**建立了自己的判据**。
- TTC 条件的自由作答：
  - 被试 #4：「我没用这个系统，靠自己的距离感减速」；
  - 被试 #15：「**FOCWS 报警非常频繁。每次报警我就踩刹车**」；
  - → 说明这些被试认为 TTC-FOCWS 提供的信息不恰当，无法建立使用判据。
- 选择 TTC-FOCWS 者的理由（Q.2-e-2）：#5、#7、#10：「**界面简单易懂**」；#13：「（用 DCA-FOCWS 时）**驾驶中我腾不出时间去判断条形的颜色**」。**且没有任何意见认为 TTC-FOCWS 在碰撞风险评价上更优。**
- 选择 DCA-FOCWS 者的理由：#1：「用 DCA-FOCWS 时没发生碰撞，**而且碰撞报警的时机也恰当**」；#4：「能判断情境是否安全，**对提升我的驾驶技能有用**」；#9：「用了系统驾驶变轻松，条形变色也易懂」；#15：「**用 TTC-FOCWS 时驾驶变得更危险**」。

### 4.5 主观评价与 DSQ / 绩效的关联
- **按 Q.1-a 分三组**：
  - Group 1（#1、#2、#8、#12、#14）：认为**条形有用（4–5 分）但黄框无用（1–3 分）**；
  - Group 2（#3、#5、#11）：认为**黄框有用但条形无用**；
  - Group 3（#4、#6、#7、#9、#10、#13、#15、#16）：其他。
- DSQ 结果（Fig. 11）：**Group 2 的「驾驶犹豫（Hesitation for drive）」与「事故焦虑（Anxiety about accident）」得分高于其他两组**。
  - → 推论：**对驾驶持消极态度的驾驶员倾向于偏好 PDCA 黄框而非 ODCA 条形，因为他们试图更谨慎地驾驶**。且 Group 2 的 #3、#11 正是 4.3 节中主动拉开车距以避免黄框出现的被试。
- **按 Q.2-e 分两组**：
  - **Group A（#1、#3、#4、#6、#8、#9、#11、#15）**：选择 DCA-FOCWS；
  - **Group B（#2、#5、#7、#10、#12、#13、#14、#16）**：其他。
- 结果（Fig. 12）：**Group A 中三个指标（碰撞次数、brake-on TTC、brake-on ODCA）的驾驶条件主效应全部显著，且在 DCA 条件下全部变得更安全；Group B 中三个指标均无统计显著差异。**
  - → **偏好 DCA-FOCWS 的驾驶员正是从该系统中获得了绩效改善的那些人**；Group B 因绩效未改善，故不愿在真实驾驶中使用。

## 五、对 AR-HUD 行人预警时空设计的启示

### 5.1 时间参数（本课题核心，穷尽列举）

**（1）预警时机 / TTC 阈值**
- **TTC 报警阈值：TTC < 4.0 s**（本文用于对照的 TTC-FOCWS 的触发阈值）。出处：作者前作 Hiraoka et al. (2008, 15th ITS World Congress)，**在同一驾驶模拟器环境中被确定为恰当的报警时机阈值**。
- **本文的负面证据（关键）**：即使采用 TTC 4.0 s 这一「已被前作确定为恰当」的阈值，**TTC-FOCWS 仍出现「报警太晚」的现象**——Pattern 1 中 **Rt2 为负值**，即许多被试在报警前就已踩刹车；且被试 #15 反馈「报警非常频繁」。
  - → **这说明单一固定 TTC 阈值（即使是 4 s）无法适应「后车正在加速」这类动态情境**；这是本课题必须显式记录的对「TTC 4 s 有效」这一论断的**反例**。

**（2）减速度阈值（本文的核心贡献，DCA 系列）**
| 阈值 | 值 | 作用 |
|---|---|---|
| **ODCA 报警触发** | **4.0 m/s²** | 声音碰撞报警的触发阈值 |
| **ODCA 报警解除** | **2.0 m/s²** | 报警持续到 α_o < 2.0 m/s² 才解除，**目的是避免极短促的报警（滞环设计）** |
| **PDCA 黄框显示** | **4.0 m/s²** | 潜在风险的前置提示 |
| **PDCA 假设的前车急减速度** | **0.6 G = 5.88 m/s²** | PDCA 定义的前提 |
| **界面量程** | ODCA/PDCA 条形 **0–6.0 m/s²** | 顶端 6.0、底端 0 |
- **滞环（hysteresis）设计是本文对时序设计的独立贡献**：**触发 4.0 m/s² / 解除 2.0 m/s²，即 2 : 1 的滞环比**，明确目的是「避免极短促的报警（very short-term warning）」。这一原则可直接迁移到 AR-HUD 行人预警的显示/撤除阈值设计。

**（3）驾驶员反应时基线（含分位数与状态相关的偏移）**
- **T = 1.2 s（刹车踏板未被踩下，b_r = 0）**；
- **T = 0.2 s（刹车踏板已被踩下，b_r > 0）**；
- **分位数信息**：前作把 T 定为常数 **1.21 s**，因为**模拟器实验中全部记录反应时的 90% 都在 1.21 s 以内**（→ **1.21 s ≈ 反应时分布的 90 百分位**）。
- **「反应」的定义（重要）**：本文明确「此处的『反应』指的是**从驾驶员决定行动的瞬间到行动完成的瞬间**这一过程」（即含决策 + 动作执行，非仅感知延迟）。
- **反应时内不可避免的判据（Eq. 1）**：`x_r0 + v_r0·T + ½·a_r0·T² < 0` ⇒ **若碰撞将在反应时 T 内发生，则即使报警驾驶员也无法避免**。这是「预警时机的绝对下界」的形式化表达。
- **论文未报告** Rt1、Rt2 的具体秒数（仅图示与定性比较）。

**（4）预警持续时长**
- 由滞环规则隐式决定：**从 α_o 越过 4.0 m/s² 起，持续到 α_o 降至 2.0 m/s² 以下**。**无固定秒数**。
- 论文明确该规则的目的是**避免过短的报警**——反向说明「过短的报警」是一个应避免的设计缺陷。

**（5）分级预警的时序结构与级间间隔**
- **本文是一个两级（PDCA 前置 + ODCA 报警）+ 连续可视化的完整分级样本**：
  - **第 0 级（连续状态显示）**：ODCA 条形高度连续变化；**颜色按减速充分性二值切换（浅蓝 = −a_f0 ≥ α_o 减速足以避撞；橙色 = 减速不足）**；
  - **第 1 级（潜在风险预告）**：**PDCA > 4.0 m/s² → 黄色边框**（含义：前车若在此刻急减速 0.6 G，你将需要 > 4.0 m/s² 的减速度）；
  - **第 2 级（碰撞报警）**：**ODCA > 4.0 m/s² → 听觉报警**，直到 ODCA < 2.0 m/s² 解除。
- **级间间隔不是固定秒数，而是由「潜在风险」与「显性风险」的物理差异决定**——PDCA 假设前车会急减速，ODCA 假设前车维持当前加速度，故 PDCA ≥ ODCA 恒成立，**黄框必然先于听觉报警出现**。这是一种**基于运动学假设强度的自然分级**，比固定时间间隔的分级更具适应性。

**（6）AEB 触发时刻**
- **论文未明确报告**——本文的 FOCWS 只是**预警**功能（视觉 + 听觉），不含自动制动介入。

**（7）其他时间参数**
- 副任务节奏：**每 2 秒**给出两个数字（心算加法）；
- 并行车速度：**滞后前车 1 秒**；
- Pattern 4 的前车行为：**以 50 km/h 行驶超过 60 秒后以 0.4 G 减速**；
- 前车在评价区段外的随机加减速幅度：**0.1–0.3 G**；
- 前车最大速度 **80 km/h**；全程停车 **18 次**。

### 5.2 空间参数
- **呈现位置**：论文未报告界面在座舱中的具体位置（Fig. 2 只给出界面本体，Fig. 3 为模拟器正视图）。界面为**仪表显示（meter display）内的条形**，**非 HUD**。
- **空间参照系**：**屏幕坐标系（screen-fixed）** 的抽象条形图，**不是世界坐标系的贴合式标注**。
- **形态与动效**：
  - 垂直条形（vertical bar），**垂直伸缩**；
  - **颜色与伸缩方向按刺激-反应兼容性（Fitts & Seeger 1953）设计**——这是本文唯一明确的空间/图形设计原理；
  - 颜色编码：**浅蓝（减速充分）/ 橙色（减速不足）**；**黄色边框（PDCA > 4.0 m/s²）**；对照 TTC 界面用**橙色条**；
  - 前作用「内黄条 + 外红条」双条，因**过于复杂造成困惑**（「不明白该盯红条还是黄条」）而被本文简化为**单条 + 边框**。
- **透明度、闪烁频率、占空比、FOV、偏心度**：**论文未明确报告**。
- **重要的界面简化教训**：**并发的两个连续量（PDCA + ODCA）用两条并列条形会造成困惑；改为「一个连续量（条形高度+颜色）+ 一个二值量（边框有/无）」后可用性提升**。这对 AR-HUD 多目标/多层级信息呈现有直接借鉴价值。
- **界面复杂度的代价（负面证据）**：被试 #13 反馈「**驾驶中我腾不出时间去判断条形的颜色**」；部分被试选择 TTC 界面正是因为「**简单易懂**」。→ **信息量与判读成本存在明确权衡**。

### 5.3 可直接写入设计规范的条目
1. **若**目标是「让驾驶员能实际避免碰撞」，**则**报警判据应用**所需减速度（DCA）** 而非 TTC——本文实验证明 DCA 条件的碰撞次数显著更少（F(2,30) = 4.33, P < 0.05）、brake-on TTC 显著更大、brake-on ODCA 显著更小。（第 4.1 节，p. 574）
2. **若**采用减速度判据，**则** 报警触发取 **ODCA > 4.0 m/s²**，解除取 **ODCA < 2.0 m/s²**（**2:1 滞环，目的是避免极短促的报警**）；可视化量程取 **0–6.0 m/s²**。（第 3.1–3.2 节，pp. 572）
3. **若**要提供「潜在风险」的前置提示，**则**用 PDCA（假设前方目标以 **0.6 G = 5.88 m/s²** 突然减速）超过 **4.0 m/s²** 时显示一个**二值化的边框/包围提示**，与连续量分离编码。（第 2.5、3.2 节）
4. **若**需要估算驾驶员反应时，**则**取 **1.2 s（未预备制动）**与 **0.2 s（已在制动）**两档；**1.21 s 对应反应时分布的 90 百分位**。（Eq. 2，p. 571）
5. **若**要判定「预警是否已太晚」，**则**用 `x_r0 + v_r0·T + ½·a_r0·T² < 0`——满足该式即表示碰撞将发生在反应时内，报警已无意义。（Eq. 1，p. 571）
6. **若**采用 TTC 阈值，**则** 4.0 s 是一个在同类模拟器环境中被验证过的取值，**但本文证明它在「本车正在加速」的情境下会太晚**（Rt2 为负）；因此**固定 TTC 阈值应至少按本车加速度做修正**。（第 3.3、4.2 节）
7. **若**界面需同时呈现两个连续风险量，**则不要**并列两条连续条形（会造成「该看哪条」的困惑）；改为「一个连续量（高度 + 二值颜色）+ 一个二值量（边框）」。（第 3.1–3.2 节 + 前作反馈）
8. **若**图形采用条形/进度式编码，**则**颜色与伸缩方向应满足**刺激-反应兼容性**（Fitts & Seeger 1953）。（第 3.1 节）
9. **若**要预测个体差异，**则** DSQ 中「驾驶犹豫」与「事故焦虑」得分高者更偏好**潜在风险（PDCA）提示**并会主动拉开车距；这类驾驶员从系统中获益最大。（第 5.2.2、4.3 节）
10. **若**系统能提供「可自行建立判据」的连续信息，**则**驾驶员会自发形成安全策略（「努力让条形保持蓝色」「黄框出现就拉开车距」），从而在预警之外获得**预防性收益**；而单纯 TTC 报警只会诱发「报警就踩刹车」的被动反应。（第 5.3 节）

## 六、本文局限性与未来工作

作者自陈（第 6 节结论）：
1. **界面可理解性仍有问题**：部分被试回答**视觉信息的内容不易理解**。未来工作是探讨 DCA 的其他呈现方式以降低驾驶员视觉负荷，**明确点名「抬头显示器（head-up display）[18, 19] 与触觉反馈系统（haptic feedback system）」**。
   - **注**：论文引用的 [18] Vassilis & Stylianos (2010, *Cogn. Technol. Work* 12(1), pp. 41–50)「Human-machine collaboration through vehicle head up display Interface」与 [19] Park & Kim (2012, 19th ITS World Congress, AP-00162)「Driver-view based augmented-reality HUD system: concept and background」——**即本文明确指向了 AR-HUD 作为 DCA 呈现载体的方向**，这使本文与本课题产生直接的引用关系。
2. **假设系统无误报与漏报**：实验建立在 FOCWS 不产生误报（false alarm）与漏报（missing alarm）的假设上；但系统故障时**反而可能增加碰撞风险**（引 Abe & Richardson 2006 [20]）。下一步将验证误报与漏报对驾驶员行为的影响。
3. **样本量不足**：「16 人不足以完全验证有效性」，计划追加实验。
4. **未报告反应时的绝对数值**（Rt1、Rt2 仅图示）。
5. **场景限于纵向前车急减速**，未涉及行人、横向目标、路口。
6. 未考察长期使用后的行为适应与依赖。

## 七、与本课题的关联与引用建议

### 7.1 可用于论文哪一章
- **时间参数章（核心）**：本文是**「减速度阈值」这条独立技术路线的完整参数源**：ODCA 触发 4.0 m/s² / 解除 2.0 m/s²（2:1 滞环）、PDCA 阈值 4.0 m/s²、前车假设减速度 0.6 G = 5.88 m/s²、反应时 1.2 s / 0.2 s（1.21 s = 90 百分位）。
- **时序结构章**：滞环设计（避免极短促报警）与「基于运动学假设强度的自然分级（PDCA 先于 ODCA）」是两个可直接迁移的时序原则。
- **TTC 阈值的边界条件章（重要）**：本文提供了「**TTC 4 s 在本车加速情境下太晚**」的直接实验证据（Rt2 为负值），是本课题讨论「固定 TTC 阈值局限」的最有力引用。
- **界面复杂度与判读成本章**：双条→单条+边框的简化教训；「腾不出时间判断颜色」的负面反馈。
- **未来工作章（本文明确指向 AR-HUD）**：作者结论中把 HUD 与触觉反馈列为 DCA 呈现的下一步方向，并引 Park & Kim (2012) 的 AR-HUD 概念论文——**这为本课题「把 DCA 类指标搬到 AR-HUD 上」提供了直接的、来自源作者的合法性依据**。

### 7.2 与已收录文献的一致与冲突

**一致之处**
- 与 `90_2010_Suzuki` 一致：都明确批评单一 TTC 判据不足。Suzuki 的理由是「TTC 不适用横向接近」，本文的理由是「TTC 不反映本车当前加速度」——**两条批评互补，共同构成「TTC 不足」的完整论证**。
- 与 `81_2016_Phan` 一致：Phan 也把 **RDP（Required Deceleration Parameter = v²/(2rg)）** 作为 TTC 的替代候选，且明确 `RDP = v/(2·TTC·g)`。**RDP 与本文的 DCA 属同族指标**（都是「避撞所需减速度」）。但 Phan 的 RDP 分类性能（k=4 时 56.5% TPR）远低于其 MGHMM（78.2%），而本文的 DCA 在行为层面显著优于 TTC——**两者结论不冲突**：Phan 是把 RDP 用作「驾驶员是否已觉察」的分类器（用途不同），本文是把 DCA 用作「是否报警」的判据。
- 与 `74_2006_Abe`（报警时机与驾驶员信任，本文引为 [20]）一致：本文明确承认系统故障（误报/漏报）时反而可能增加碰撞风险，并把该问题列为下一步。
- 与 `84_2022_Char` 一致：Char 的 `LTTB = V²/(2|a|)` 与本文的 DCA 是同一物理量的两种形式（Char 求距离，本文求减速度）。Char 用 −8 m/s² 的最大减速度，本文的报警阈值 4.0 m/s² 恰为其一半——**即本文在「所需减速度达到最大制动能力的一半时」就报警**，这是一个可写入规范的比例关系。

**冲突之处（必须显式指出）**
1. **与「TTC 4 s 为行人/前向预警恰当时机」的冲突（本文提供直接反例）**：
   - `90_2010_Suzuki` 采用 TTC 4.0 s 作为呈现上界（源自 Ueda 2007）；`70_2016_Kang` 比较 TTC 2 s vs 4 s。
   - 本文的 TTC-FOCWS **正是用 TTC 4.0 s**（且该阈值由作者前作在同一模拟器中确定为「恰当」），结果却是：**Pattern 1 的 Rt2 为负值（被试在报警前已制动）**，且被试反馈「报警非常频繁」，主观上一致认为 DCA 的报警时机更优（Q.2-d 得分为 2）。
   - **可能原因（边界条件）**：① **场景动力学不同**——本文的 Pattern 1 是「本车正在加速追赶前车时前车突然急减速」，TTC 在本车加速时会**低估**风险，故 4 s 阈值触发过晚；Suzuki/Ueda 的场景是「匀速接近斑马线」，TTC 不失真。② **模态与强度不同**——Suzuki 的 4 s 是**低强度的黄色情境信息**，本文的 4 s 是**听觉报警**，后者若时机不当会被感知为频繁扰人。
   - **调和结论（本课题可贡献点）**：**TTC 阈值只在「相对速度近似恒定」的情境下有效；一旦本车或目标存在显著加速度，应改用所需减速度（DCA/RDP）判据，或对 TTC 阈值按本车加速度做动态修正。**
2. **与 `09_2025_叶明慧`「预警图形持续 3 s」的差异**：本文的预警持续时长由 **4.0 → 2.0 m/s² 滞环**决定，无固定秒数；且本文明确「避免极短促的报警」是设计目标之一。
   - → 二者可整合为：**固定最小持续时长（如 3 s，保证可被察觉）+ 滞环解除条件（保证不过早撤除也不无限持续）**。这比单纯固定 3 s 更稳健。
3. **与 `81_2016_Phan` 在「界面信息量」上的张力**：Phan 发现**贴合式边界框（简单、直接定位）被 17/25 被试偏好**，而非贴合式警告面板被认为「迫使制动、造成分心」；本文发现**信息更丰富的 DCA 界面在客观绩效上更优，但主观易懂度与使用意愿两极分化**，且有被试因「简单易懂」而选择信息更少的 TTC 界面。
   - → **信息量与判读成本的权衡是跨文献一致的张力**。设计规范应写明：**连续风险量（如 DCA 条形）不宜作为主要预警通道，宜作为「可选的辅助态势信息」；主预警通道应保持简单的二值/分级编码（如贴合式边界框的有/无）。**
4. **与本课题「行人场景」的适用性边界（必须声明）**：本文全部为**纵向前车追尾**场景。DCA 假设「前车沿同一路径」，对**横向冲入的行人不直接适用**——需要先把行人的横向运动转换为「本车路径上的等效障碍出现时刻」（可借用 `90_2010_Suzuki` 的 T_p 或 `92_2016_Kuo` 的双侧 TTA），再计算 DCA。**这一「T_p/TTA → DCA」的两级串联是本课题可提出的整合方案。**

> **Takeaway**：本文给出「用所需减速度替代 TTC」的完整参数体系——ODCA 报警触发 4.0 m/s²、解除 2.0 m/s²（2:1 滞环以避免极短报警）、PDCA 假设前车 0.6 G = 5.88 m/s² 急减速、驾驶员反应时 1.2 s（未制动）/ 0.2 s（已制动，1.21 s 为 90 百分位）；16 人模拟器实验证明 DCA-FOCWS 的碰撞次数显著少于 TTC 4.0 s 阈值的 FOCWS（F(2,30)=4.33, P<0.05）。
